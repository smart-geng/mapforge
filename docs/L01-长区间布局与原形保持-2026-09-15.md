# L01长区间布局：原形保持与真实拒绝

2026-09-15，未提交。**长区间布局试验已完成，仍没有合格修复，没有新XODR，未应用到Web。** 两种布局都能使指定点到位，但其他位置/边界失败，不能拿局部改善交付。

## 本轮实现

新增`mapforge/repair_web/outer_event_layout.py`及`scripts/check_outer_event_layout.py`。仅允许road11事件末两个非语义长结点移动：五边界共同54系数/24自由方向，区间仍至少6m；源身份、出生位置、参考轴、作用域端点、ID/速度/TOPO不变，不增加独立结点。

关键原形问题已核实：移动结点后，原分段三次曲线一般不在新基空间中。本次两布局对原XML的最小形变投影分别仍有 **0.100143m / 0.066401m** 最大偏差，不能说“只是换一种表示，地图没变”。

因此实现以下契约，而非自动迁移用户地图：

- 零操作和撤销基准直接返回原XML字节；禁止把投影系数当零操作地图写出。
- 投影只作为新候选的数值初值，来源/曲率/反向量阈值仍来自原r6实际XML，不重置为投影后的较坏值。
- 最小形变积分对**原XML**计算，在新长区间与实际旧XML分界的并集上积分；积分小区间不是输出曲线结点。该积分另用多项式原函数核对。
- 每个布局重新构建共同基函数、完整原件交域、宽度、端口与临界点；全来源域长度/对象身份及movement完整保留。

`CurvatureFairing`仅把目标残差从隐含`M·reference`显式化为`objective_reference`，旧固定布局计算仍等价；原Web冻结内核未改。

## 收敛后的下一工作包

**停止这两种固定布局的追加试算，也不继续枚举更多布局。** 当前结果不支持“挪一下结点就能闭环”的结论。后续先解决用户拖动的影响范围与可编辑自由度，而不是再次直接最小化形变：

1. 在同一五边界共同模型中，将未选中曲线的保持范围、选中曲线的实际支撑范围声明为编辑契约；锁定的是未编辑几何，不是冻结父路再逐条重建连接路。当前范围内不涉及路口口部，不能外推成L02已完成。
2. 先计算在原形/端口/C2保持下还有多少可用自由方向，检查控制点能否影响它们；零自由度就明确报出，不能让求解器暗中扩大影响域或移动邻线。
3. 只有原形保持成立，才讨论更丰富的**长区间**表示。不得默认移动结点后近似投影等于无损迁移；不得按源点插短段。任何结构变化必须先登记区间长度、数量、身份对应、零操作及撤销策略，再做有限候选，不在本轮追加执行。
4. 求解流程先恢复共同约束可行性，再最小形变；数值失败与实际约束矛盾分开诊断。研究不退步护栏仍单独列账，不伪称用户/标准门槛，也不静默删除以换通过。
5. 最终完整目标必须实际XML回读、原件叠图和全部邻边复核通过后才可接Web。当前没有可替换用户地图的版本。
