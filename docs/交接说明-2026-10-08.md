## 1. 背景与目标

**项目**：面向车路协同与自动驾驶的语义地图编译工厂。源格式 → 统一中间表示 → 目标格式，每次转换都输出质量报告、损失报告、ID 映射和来源清单。交叉口是第一公民。首批格式是 OpenDRIVE、SHP（Profile 驱动，现为 `ibd-smarteditor-v1`）、V2X MAP（T/CSAE 53-2020 体系）。

**用户的当前主线**：纯离线把 **SHP→XODR** 和 **MAP XML→XODR** 做好。具体是：

- 忠实原件；
- 世界坐标下的车道边缘和路口要平滑；
- 不能用密集短段冒充平滑，下游消费者包括自动驾驶；
- MAP 缺真实出口时，按同一进口方向左右镜像并标 INFERRED。

用户最近两次的要求：

- 10-07：“优化得到平滑且准确的地图，可自行查资料找方案解决”（目标模式）。取舍自己查证据决定，并标“自定、待复核”。
- 10-08：“继续，还有哪里能优化”。

**本地数据**（只读原件，不许改）：

- `shp_0222-0326/`：IBD 车道级 SHP，44 图层，重庆金凤，163 个路口。
- `v2x_map_xml/`：7 个现网路口的 MAP XML、消息层送审稿 docx 和 TCI asn。
- `OpenDRIVE_1.4H.xsd`、`OpenDRIVE_1.5M.xsd`。
- 资料的事实以 [资料盘点](资料盘点-金凤示范区数据与标准资料.md) 为准。

**几何质量以评分板为准**：

```
python -m mapforge.score --out out\scoreboard\<名称>
```

- 评分对象是 7 个路口的 SHP 和 MAP，共 14 份。
- 策略文件 `profiles/validation/static-acceptance-v1.draft.yaml`，现为 0.7-draft，分 T1（结构、G8 保真、esmini 等）和 T2（更严的保真与口部光滑）。
- 另有不分级的报告项，如光顺 `fair_*`、连接路边缘拼接。
- 改几何必须给评分板前后对比，草案阈值不能为了让候选通过而改。

## 4. 换机：在新电脑上第一次要做的事

1. **盘符**：把这块盘挂成 **E:**。
   - 证据、登记和文档里有大量 `E:\MapFactory` 绝对路径。
   - 再执行 `subst F: E:\`：旧证据里的 `F:\MapFactory` 路径靠它解析。subst 重启后失效，每次开机要重做，或放进开机脚本。
2. **系统**：Windows。原因有三：
   - esmini 动态库是 `E:\MapFactory\esmini\bin\esminiRMLib.dll`，随盘带着；
   - 评分板的 esmini 检查用 ctypes 载入它；
   - 文档里的命令是 PowerShell。
3. **Python 环境**：现有 `.venv` 不能用，它指向原机 C 盘的解释器（`.venv\pyvenv.cfg` 的 home）。要重建：
   ```powershell
   # 安装 uv（原机 0.12.21，用相近版本即可），然后：
   uv python install 3.11.16
   cd E:\MapFactory
   Remove-Item -Recurse -Force .venv
   uv sync --frozen
   ```
   - 版本锁在 `uv.lock`，`requires-python ==3.11.*`。
   - **不要升级到 3.12**：3.12 的 `sum()` 改了浮点求和，冻结证据的数值会变。
   - `uv sync` 需要能访问 PyPI。新机器离线时，要先在能联网的机器上用同一 `uv.lock` 下载好 wheel 带过去。
4. **git**：
   - 新机器上盘的属主不同，先 `git config --global --add safe.directory E:/MapFactory`，否则每条 git 命令都要加 `-c safe.directory=*`。
   - 原机的 `core.autocrlf=true` 来自 Git for Windows 的系统配置，不在仓库里。新机器若不是这个设置，先在仓库里设 `git config core.autocrlf true`，否则 `git status` 会把大量文件报成已修改。
   - **绝不要**用 `git checkout/restore/stash/reset` 改写工作区文件：会改换行，破坏证据绑定（见第 5 节）。
5. **验证环境**：
   ```powershell
   .\.venv\Scripts\python -m pytest -q          # 原机 2026-10-08：1343 通过、11 xfail（含机器相关的冻结证据重放），约 23 分钟
   .\.venv\Scripts\python -m mapforge.score --out out\scoreboard\<日期>-newmachine
   ```
   - 换 CPU 后浮点末位可能不同。replay.py 记过 2026-10 换到只有 AVX2 的机器后，冻结重放差到相对 5e-15。
   - 所以新机器的评分板与定版不一定逐字节相同。比指标（`scoreboard.json`），不要只比文件哈希；等级和指标应当一致到很小的容差。
6. **其他**：
   - 评分板一次全量生成加评分约 1 小时（4 进程；与别的任务同跑会更久）。
   - 泛化集完整管道 16 个路口约 1.5–2 小时（4 进程）。
   - `out/` 约 3 GB 研究证据，只追加，不要清理。

## 5. 工作规则（用户的要求和多轮反馈）

- **始终用中文回复用户**；不自动 commit / push，除非用户明确要求。
- **评分板是裁判**：
  - 改几何要给出评分板前后对比；
  - 不能用单点、单项检查或测试数量宣称完成；
  - 草案阈值不能为了让候选通过而改。
- **注意全局，不能拆东墙补西墙**：
  - 每次改动后逐文件对比上一定版的全部指标，不只看目标指标；
  - 有变差的要逐车道、逐路查清再说完成；
  - 只针对 SHP 的改动，MAP 输出必须逐字节不变。
- **定版流程**：
  1. 实现；
  2. 扫参或试验；
  3. 撤掉试验设置（曾经把 0.10 m 的试验带宽漏进定版，只能重跑）；
  4. 全量评分板生成；
  5. 生成结果另存 `scoreboard.generated.json`，再 `--no-generate --register "<说明>"` 登记到 `experiments/registry.jsonl`；
  6. 更新阶段文档、HANDOFF、`experiments/README.md`、优化方向计划、评分板基线、CLAUDE.md 与 AGENTS.md（CRLF），以及环境迁移记录里的测试数；
  7. 跑全量 pytest；
  8. 用中文汇报前后对比表和剩下的失败及成因。
- **评分板生成期间不要改管道代码**：子进程开始时才导入模块，中途改会得到新旧混合的结果。
- **用户授权“自行查资料找方案”时**：取舍不要推回给用户。
  - 查标准原文、跨源真值（如同一路口 SHP 与 MAP 互为参照）、做物理推导和试验，然后自己定；
  - 在文档或策略里标“自定、待复核”，并保持可撤回。
- **证据绑定**：`out/` 研究证据按字节哈希锁定了很多代码文件。
  - `python scripts\bound_files.py <文件>` 可查某文件是否被锁；不带参数列出全部。
  - 另有 CLAUDE.md 列出的 `cli.py`、`decision.py`、`tests/conftest.py` 等，按被锁对待。
  - 已知被锁的包括 `shp_to_xodr.py`、`refline_fit.py`、`map_to_xodr.py`、`writer.py`、`junction_surface.py`、`smoothness.py`、`g11.py`、`profile_source.py`、`ibd_reader.py`。
  - 新功能写进新模块，像本轮的 `leg_fit_fallback.py` 那样，在默认管道里包一层、只在原逻辑失败时接手。
- **CRLF 文件**：CLAUDE.md、AGENTS.md、`profiles/validation/static-acceptance-v1.draft.yaml`，改时保持 CRLF。
- **硬约束**：
  - phaseId 绑定禁止自动推断；
  - region/node ID 只从台账取，重生成必须出 id-diff；
  - CRS 缺失或可疑就停止生产转换；
  - 原件只读；
  - 未识别图层/字段走 PASSTHROUGH，不丢弃；
  - 许可证限制见 CLAUDE.md；
  - 9 处已批准的零宽出生来源角色只在原对象生效。
- 不要动别人起的进程；只停自己启动的。

## 6. 常用位置和命令

| 内容 | 位置 |
|---|---|
| 默认转换流程 | `mapforge/pipeline.py`（`python -m mapforge.cli convert`） |
| SHP 生成器（受绑定） | `mapforge/ops/shp_to_xodr.py`；口部前移入口 `mapforge/ops/shp_mouth_envelope.py`；参考线兜底 `mapforge/ops/leg_fit_fallback.py`；路口辅助铺面 `mapforge/ops/envelope_surface.py` |
| MAP 生成器（受绑定） | `mapforge/ops/map_to_xodr.py`；源修正 `profiles/source-corrections/` |
| 后处理变体 | `mapforge/ops/lane_refit.py`（默认 `g2-k04-c2`）及其调用的各模块（见 CLAUDE.md“当前入口”） |
| 评分板 | `mapforge/validate/scoreboard.py`，`python -m mapforge.score`；策略 `profiles/validation/static-acceptance-v1.draft.yaml` |
| 泛化集 | `mapforge/validate/generalization.py`；路口清单 `profiles/validation/generalization-set-v1.yaml`；登记 `experiments/generalization.jsonl` |
| 泛化诊断脚本 | `scripts/generalization/`：`generator_stage.py`（只跑生成阶段，可 `--all`）、`surface_diag.py`（铺面为什么失败）、`leg_fits.py`（进口道路拟合采集与兜底标定） |
| 运行登记 | `experiments/registry.jsonl`（评分板，只追加，同一运行以最后一行为准）；说明见 `experiments/README.md` |
| 运行输出 | `out/scoreboard/<运行名>/`、`out/generalize/<运行名>/` |

```powershell
# 单个路口
.\.venv\Scripts\python -m mapforge.cli convert shp_0222-0326 --like v2x_map_xml\<case>.xml --to xodr -o out\<名>.xodr
.\.venv\Scripts\python -m mapforge.cli convert shp_0222-0326 --at <lon>,<lat> --to xodr -o out\<名>.xodr
.\.venv\Scripts\python -m mapforge.cli convert v2x_map_xml\<case>.xml --to xodr -o out\<名>.xodr
# 评分板（生成 + 评分 + 登记）
.\.venv\Scripts\python -m mapforge.score --out out\scoreboard\<日期-名称> --register "<说明>"
# 泛化集
.\.venv\Scripts\python -m mapforge.validate.generalization --out out\generalize\<日期-名称> --register "<说明>"
# 复现旧证据（旧口部、无后处理）
.\.venv\Scripts\python -m mapforge.cli convert <SHP目录> --like <MAP.xml> --to xodr --shp-mouth legacy --post none -o <输出.xodr>
```
