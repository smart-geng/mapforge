# 面向地图工程师的交互式地图修补工作台

2026-10-08。状态：产品与实施规划，尚未实现本文新增功能。用户已确认首批使用者为地图工程师，任务为“导入、修形、检查、交付”；允许人工修补，优先让客户通过交互页面完成工作。自动化程度不再作为首个客户版本的主门槛。

> **同日评审修订**：任务分解、依赖、验收和当前执行顺序以 [评审与实施计划](评审与实施计划-交互式地图修补工作台-2026-10-08.md) 为准。首轮只做一种实证可行的编辑操作；源工程/页面不等待几何探针。原 7–11 周估算不作为承诺排期。

本规划接续现有 SHP→XODR、MAP XML→XODR 主线，调整后续产品化顺序。几何质量、来源追溯、原件只读、CRS/phase/ID 规则继续有效；不重启冻结的 L01 准入链和 L07 整图求解器。旧 GUI 方案中的研究执行顺序保留作历史，本阶段按本文推进。

## 1. 产品目标与首发边界

首发目标：地图工程师无需写 Python、改 XML 或寻找研发人员代改，能够导入指定规格的数据，发现问题，在地图上调整，保存工程，复验后交付约定用途的 XODR。

核心流程为：**导入原件 → 建立可编辑工程 → 自动生成建议 → 人工修补 → 检查实际结果 → 保存及交付**。自动生成失败仍能回到源对象和编辑草稿；成功生成不等于可交付。

首批范围：

- Windows 本地运行，浏览器作为交互页面；断网可使用，数据留在客户机器。
- 首先支持现有 IBD SHP Profile，再接入当前 MAP XML 方言；编辑以单个平面路口及关联进出口道路为单位。
- 首个完整编辑闭环先在 SHP 上验收，MAP 源查看可并行；MAP 编辑未完成时界面明确只读，不能借 SHP 的成绩宣称两条线均支持。
- 输出采用现有 writer 已验证的 OpenDRIVE 1.5 路线；客户消费端及其版本在试点前固定。更高版本逐项建立兼容矩阵后开放。
- 以二维俯视、源数据叠图和横断面为主要工作面；三维只读检查可后续接入同一编译产物。
- 首版不承担任意图商接入、任意 XODR 无损编辑、跨路口整城编辑、多层立交、材质/建筑/天气/交通参与者场景制作。输入有高程时保留并报告，超出支持范围的高程/超高编辑明确限制。
- MAP 缺真实出口时沿用同进口左右镜像并标 INFERRED；客户绘制或调整的假设仍保留其来源性质，不能标成测量真值。

“手工可用”的含义是人能表达必要的几何和业务决策，系统负责编译、联动、检查和记录。人工操作不能把没有证据的通行关系、CRS、相位或区域编号变成事实。

## 2. RoadRunner 的可借鉴交互

以下为 2026-10-08 核对的 MathWorks 官方说明，以及本项目据此作出的设计选择；不代表已实现同等能力，也不新增 MATLAB/RoadRunner 运行依赖。

- **先选道路，再显示控制柄。** Road Plan Tool 支持拖动控制点、属性面板精确输入；相连道路端点移动会联动相邻道路方向。工作台采用同样的对象操作顺序，并在修改前显示全部影响对象。[Road Plan Tool](https://www.mathworks.com/help/roadrunner/ref/roadplantool.html)
- **车道工具按业务对象划分。** 官方教程分别介绍车道添加、类型、宽度与标线。工作台先开放宽度和共享边界，渐变/出生事件随后加入，避免让地图工程师编辑多项式系数。[Customizing Lanes](https://www.mathworks.com/solutions/automated-driving/roadrunner-tutorial/customizing-lanes.html)
- **路口具有独立编辑入口。** 官方教程支持从道路端部手工建立路口，也提供角部与停止线工具。本项目把口部、已有转向对应和铺面支撑作为独立对象；已有源 TOPO 不因几何相交而自动改写。[Creating Junctions](https://www.mathworks.com/solutions/automated-driving/roadrunner-tutorial/creating-junctions.html)
- **检查将要导出的实际表示。** 官方入门示例提供 OpenDRIVE 导出预览。本项目采用“实际候选读回视图 + 导出检查”，防止画布曲线和最终文件不同。[Create Simple RoadRunner Scene](https://www.mathworks.com/help/roadrunner/ug/create-simple-roadrunner-scene.html)

首版重点借鉴对象选择、精确操作、关联更新和导出检查。完整三维场景资产库不列入本阶段。

当前代码基线 `main` 的 `17a22d2`；几何定版 `20261008-safe-mouth-recovery-v3`。评分板 T1/T2 14/14；泛化 16 个转出 10、T1 8、T2 2。新方案需要同时改善可编辑性和人工完成任务的能力，不能把这些数字改写成人工修补后的成绩。

## 4. 地图工程师的工作流程

### 4.1 导入与建工程

新建工程，选择 SHP 目录或 MAP XML、已有 Profile、目标路口与交付用途。读取原件清单、单位、坐标框架、图层角色和稳定对象身份，生成只读源快照或受哈希保护的项目内副本。

源读取完成即可打开画布。拟合、铺面或后处理失败时，保留能够解析的源对象、可靠的已有产物、失败位置和原始日志；缺少可靠几何的对象显示缺失及原因。首轮不要求六个失败路口都已建立完整可编辑道路/面域，也不能把临时 raw 文件当成完整结果。

坐标或单位不明时允许查看原始坐标、整理对象和补录材料；禁用米制位移与跨源吸附。局部单位和框架可证实而绝对 CRS 尚未核验时，允许本地几何草稿工作，生产转换/正式交付仍按 CRS 规则阻断。绝不能把浏览用的临时框架标为 WGS84。

### 4.2 定位问题

问题条目用业务语言：如“进口道路过短，当前口部位置会切掉整条路”“转向接头错开”“铺面存在未覆盖区”。每条包含对象、地图位置、检测范围、原因、可用操作和当前检查状态。

点击问题同时选中对象、缩放到位置并打开工具。源数据缺失、算法未能构造、几何不合格、证据待补分开显示；未知原因保留为未知，不能统一提示用户随意拖动。

### 4.3 操作与联动

选择对象后才出现合法控制柄，显示作用区间、固定端、共同边界、关联车道与连接路。拖动前高亮影响范围，拖动时可看虚影，松手或停顿后计算真实候选。

输入方式包括拖动、法向位移、站位、方向和端点数值；使用道路业务单位。精确位置与吸附是两个明确模式，吸附提示目标身份和距离，不能在失败时偷偷吸回原位。

几何吸附不自动建立拓扑。一个共享边界由相邻两车道共同引用；移动后宽度、中心线、标线和受影响连接一起更新。需要扩展联动范围时先提示，未同意则保持原草稿。

### 4.4 检查与保存

画布同时支持原件、修改前、当前草稿和实际候选。虚影明确标“意图”；正式候选由后端编译后读回显示，不用前端平滑线冒充导出结果。

保存工程不要求整图合格。允许保存待建对象、未通过的修补意图、失败原因和最后成功候选。取消或计算失败不覆盖上一已应用状态；重新打开工程继续处理。

### 4.5 交付

“保存工程”“导出研究候选”“正式交付”是三个不同动作。研究候选带完整状态清单和醒目标识；未编译成功不能产生伪 XODR。正式交付要求当前快照通过适用检查，材料齐全，输出地图、质量/损失报告、ID 映射及来源记录。

目前 T1/T2 是草案，现行正式裁决仍 BLOCKED。客户试点评估前需整理适用用途的正式策略及其批准记录；未完成时只提供明确标识的评估工程/候选，不增加“忽略所有错误后交付”开关。

## 5. 工作台页面

采用一个主工作台，避免用户在转换、预览、质量页面之间反复寻找同一对象。

- 顶部：工程、保存状态、撤销/重做、检查、导出；长任务进度与取消明确显示。
- 左侧：问题清单与对象树切换；道路、车道、边界、转向、铺面、停止线分层选择，可按阻断/警告/材料待补筛选。
- 中央：二维画布占主要空间，支持缩放、平移、框选、测量、源/结果透明度切换；比例尺和单位常驻。密集对象弹候选菜单，锁定对象有可见标识。
- 右侧：所选对象的可编辑属性、控制柄参数、源对应、受影响对象、局部预览结果；高级参数默认折叠。
- 底部：横断面或来源偏差/曲率详情、检查结果、操作历史；详细技术日志放在支持入口，不占主要操作面。
- 3D 检查使用同一候选的只读视图；二维与三维共享选择身份。首个闭环不依赖三维编辑。

键盘：Enter 应用候选、Esc 取消、Ctrl+Z/Y 撤销/重做、Ctrl+S 保存。输入框聚焦时按其本地编辑语义处理，不能触发全局误操作。

## 6. 优先实现的编辑工具

### 第一组：首轮工具候选池

下列是工具能力候选，不是首轮全部承诺。实施计划 WB-04 只选出一种实证可行的操作，精确数值和一个必要控制柄优先；其他操作在独立能力验证后再开放。

1. **选择、测量和叠图**：对象身份、源覆盖范围、方向、距离、修改前后可视对照。
2. **口部位置**：在有源支撑的合法区间内沿道路调整，明确停止线与口部的区别；联动相连车道、全部相关转向、比较窗口及铺面。
3. **局部长曲线**：指定作用范围和固定端，调整位置、切向或曲率控制意图；后端用已有长原语拟合路线编译，前端控制点不直接一一变成短几何段。
4. **共享边界与宽度**：沿法向调整共享边界或关键站位宽度，显示相邻车道的变化；正宽、合法零宽事件与来源边界分别检查。
5. **受控吸附、预览和事务**：源边界、端点及既有口部可选作目标；明确距离与身份，应用/撤销覆盖全部派生更新。

首个操作优先评估普通道路有限范围的边界修形，先查源角色、控制自由度和实际写出跨度。口部操作后置：当前只有全路口 margin 标量，0701/0629 两例降到零仍触发保留长度保护，不能承诺口部滑块可修通。探针失败时源工程线继续，编辑工具保持禁用。

### 第二组：扩展人工接管能力

6. **参考线构造与源链归属**：当自动拟合失败时，按原件建立有界长曲线，检查完整源覆盖；共享上游链显示对象所有权，禁止用重复造路掩盖拓扑问题。
7. **连接路修补**：选择已知进口/出口车道，确认已有源转向对应，编辑引导线与端部条件。原件 TOPO 不改；源语义有争议时登记问题和来源裁决，未解决不新增无证据通行关系。
8. **渐变和出生/消失事件**：修改事件站位、过渡范围及宽度意图，联动相邻车道；保留已批准九处来源角色的原对象范围。
9. **铺面与交通岛边界**：选取已有源面/边界作为支撑，调整端帽或连接区；检测自交、孔洞、穿越交通岛和来源覆盖。缺源时进入补材料流程，不能提供无条件填洞。
10. **MAP 来源与出口检查**：真实出口/镜像出口分开；中心点列与外缘观测分开，未知宽度不声称已恢复。已有 MAP 宽度审计的复合曲线适配缺口必须补齐。

普通操作不修改原件、限速或 TOPO。确需纠正源数据时，使用独立的版本化来源修正决定，显示原值、派生值、依据和影响范围；不能通过移动“比较真值”消除误差。

## 7. 已知失败如何进入人工流程

固定样本用于开发和验收追踪，不承诺下述动作已经修通。

- `0701/0629` 两个短进口或深切样本：先显示原道路支撑和保护原因，作为单 margin 不可行的负例。后续重新分析源链/结构切分，建立逐口部能力后才允许调整；不能将全局 3 m 参数变化当作局部口部修复。
- `0729` 急弯渐变匝道：源叠图下指定局部参考线与渐变范围；保留曲率、偏差和长原语约束，无可行候选时保留草稿。
- `0811` 上游链共享：先检查源链归属与切分解释，再拟合；不使用重复对象或自动改 TOPO 作为兜底。
- `0621` 分隔带尾部：让工程师选择可证实的源路口面边界作为延续支撑，再构建候选；保持分隔带身份与道路覆盖。
- `0630` 离去端帽：显示无源支撑的孔洞、出口方向和源末端；允许修正扫掠/端部解释，有真实缺料则保留待补。当前 0.200630 m² 孔洞不能因用户点击而作为数值碎缝填平。
- `061310` 已生成但接头与形状不合格：联动检查两端口和关联道路，再比较候选；已拒绝的严重反打候选仍拒绝，不能用手工模式放宽反打阈值。
- `0412` 比较窗口及停止线问题：先核源身份和关联范围，显示是哪一段在比较。测量链错误通过版本化修正解决，不让客户拖动本来正确的道路去适应错误测量。

详见 [当前失败与证据](阶段2-连接路独立候选恢复-2026-10-08.md)。自动未生成 6 个样本按四类主因分组，其内部几何机制各异，首发范围必须逐例说明。

## 8. 工程与编译架构

### 8.1 四层状态

- **SourceObservation**：只读原件、稳定 feature 身份、单位、局部坐标与 CRS 状态、源拓扑、来源覆盖。
- **EditableSceneDraft**：可未完成的道路、车道、共享边界、口部、转向、铺面与停止线关系。内部 UUID 仅为工程身份，不替代 region/node/lane 台账编号。
- **CompiledCandidate**：特定草稿产生的真实 XODR、源映射、派生记录和编译诊断；允许某次编译失败，但不混合新草稿与旧候选。
- **ValidationSnapshot**：绑定草稿、输出、源文件、工具版本、Profile 与策略的检查结果。任一输入改变，相关结论立即过期。

这是本阶段的最小编辑模型，不宣称仓库已实现完整 MapIR。初期只覆盖首发对象和操作；稳定后再向统一 MapIR 收敛。

### 8.2 编译与依赖

保留现有自动管道作为无人工意图时的基线。新增编辑编译入口接受草稿及人工意图，复用已验证的几何模块和 writer；不能只给现有 CLI 加按钮而绕不开“必须先生成 XODR”的前提。

每次修改计算明确的依赖闭包：参考线/边界 → 相邻车道与中心 → 口部 → 关联转向 → 面域与来源窗口 → 检查。外部冻结对象不动，受影响闭包共同生成和应用。它是局部有界编译，并不要求恢复旧 1681 维全图求解器。

长期任务在独立进程执行，绑定工程版本，支持取消、超时、失败定位和结果丢弃。一个工程采用单写者；过期候选、过期检查、重复提交均不能覆盖新状态。

前端仅处理交互意图与显示采样；实际计算留在 Python。沿用本地 FastAPI 服务和现有二维交互经验；先完成真实闭环再决定是否扩展前端框架，不把框架迁移作为第一工作包。

### 8.3 工程持久化

新项目 schema 保存源引用/可携带副本、完整草稿、EditIntent 操作日志、工具和规则版本、检查引用与结果哈希。应用一项编辑及其派生更新是一个事务。

草稿命令的确认与编译候选的接纳分开。身份、单位、范围及命令结构有效的意图可确认进入待处理草稿，即使编译失败也可保存/撤销/重开；保存不强制 compile。候选只有与当前草稿和输入指纹匹配才可接纳。未确认或取消的鼠标虚影不进入自动保存。崩溃后恢复最后完整事务；坏快照不覆盖上一可恢复版本。

旧研究工程只读打开或显式复制迁移，不直接复用旧 handle 标量时间线。项目移动路径后核对源哈希并重绑定；源内容变更则保留旧工程并显式建立新版本。

## 9. 编辑状态与放行规则

项目同时显示三个维度：**编辑状态、检查状态、交付状态**，不能合成一个含糊的绿色“完成”。

- 编辑状态：仅源数据 / 草稿 / 有编译候选。不可编译的意图可保存，并说明哪部分尚无候选。
- 检查状态：未检查 / 运行中 / 已过期 / 通过 / 未通过；说明局部还是整个交付范围。
- 交付状态：沿用适用策略的 DELIVERABLE / BLOCKED / REVIEW_REQUIRED；保存不改变交付裁决。

局部预览依次检查对象身份、单位/框架、正宽与曲线有效性、作用范围、来源对应及关联更新。明确标注继承失败、新增失败和已改善项。已有别处 FAIL 不阻止保存草稿，非法或未通过候选不冒充已验证几何。

正式交付前检查整个声明交付范围的来源完整性、拓扑、几何、铺面、CRS、目标格式与消费端。相位和 ID 门禁按目标用途适用，禁止自动推断。用户可选择已有批准的用途/Profile，但不能逐项随意关掉失败项。

静态质量与明确工况动力学继续分开呈现。旧门禁与静态草案的冲突需要正式规格决策，不把旧 FAIL 静默删除，也不让无关工况阻塞所有编辑操作。

## 10. 分阶段实施与退出条件

以下保留产品阶段目标；实际任务和时间检查点见评审后的 WB-00～12。首个人工控制量与编译适配尚未验证，原 7–11 周没有任务级依据，暂不作为排期基线。源工程、页面和发布材料可以并行推进。

### M0 明确合同并验证一种操作

- 定义项目状态、对象身份、共享边界与口部依赖、编辑/检查/交付状态契约。
- 固定已有 XODR 真实修补和失败源工程可打开保存两类首轮任务；无初始 XODR 经人工修通列为后续 V1 独立验收。
- 先建最薄源适配与单操作合同，优先验证有限范围边界修形；0701/0629 保留为口部单参数拒绝负例，具体探针边界见 WB-04。
- 输出真实源叠图和必要控制量，确定哪些编辑模块需要新增；检查受绑定文件影响。

编辑能力退出：至少一个有意义的人工操作产生真实可检查的候选。探针受阻不算该工具通过，但源查看、草稿事务和失败工程页面继续。仅有线框、按钮和文档不能进入“人工修补已可用”。

### M1 从源打开并保存工程

- 建立源读取与可编辑草稿，2D 画布、选择、问题定位、工程保存/重开和任务管理。
- 自动生成作为可选任务；失败的六个样本都能查看原件、失败定位和待建对象，保存后重开不丢失。
- 草稿版本、事务和异步时序先于真实操作接入；不依赖几何探针完成才建设源页面。已通过的操作再接真实候选。

退出：成功输入和生成失败输入均完成源导入、问题定位、待办意图、保存重开；不可编译意图与迟到任务处理正确。此阶段是工程管理可用，不代表修补能力已完成。

### M2 一种真实人工修补闭环

- 只完成已验证的一种操作，补齐影响范围、精确输入和实际结果检查，吸附按必要性追加。
- 已有 XODR 的真实问题通过页面得到可量化改善和独立读回；六个生成失败项目保持可查看、可保存，不宣称已修通。
- 真实修补链经历预览、草稿确认、候选接纳、撤销/重做、保存/重开和候选导出；源与范围外对象不发生未声明变化。

退出：独立地图工程师不用脚本完成声明支持的修补任务及失败工程保存任务，保留样本也有验证。可安排 V0 受控评估；正式交付仍受规格和外部材料约束。

### M3 人工接管生成失败及扩展工具

- 按 WB-11 先证明一个无初始完整 XODR 的真实人工接管任务，再用另一同类样本复验；补参考线源链、连接、渐变及源面支撑工具时逐项准入。
- 对固定 16 个样本记录“自动完成 / 人工完成 / 待外部材料 / 超出首发范围”，逐例给耗时和残留问题。
- 接入 MAP 来源、真实/镜像出口及相应编辑能力，补宽度审计；MAP 不以 SHP 的物理边界真值替代未知外缘。

退出：所有宣称支持的故障类别至少有独立真实用例从导入到完成；未解决项列入明确的支持边界。不能仅通过把困难样本移出清单提高成功率。

### M4 客户试点与发布准备

- 完成离线安装/启动器、完整前端资源、本地 Python 和 esmini 运行依赖；客户不需要开发环境或任意盘符映射。
- 正式用途、CRS 材料和固定消费端从首周的 WB-09 并行准备；本阶段完成最终同版交付验证，不能到最后才发现材料缺口。
- 试点任务覆盖陌生样本、源变更、取消、崩溃恢复、磁盘不足、重复打开、项目搬迁和导出中断。
- 完成操作手册、问题处理指引、发布说明、第三方清单和可分享的诊断包；原始客户数据默认不进入支持包。

退出：目标用户能在干净且断网的约定机器上独立完成任务，交付包与检查对应同一结果，未通过的成果无法被误认成正式交付。

宣布正式首发还须有正反两类端到端证据：每个首发宣称支持的源格式/目标 Profile 组合，至少有一份真实任务达到 DELIVERABLE；失败或检查过期的快照不能正式导出。该正例只是交付链最低证明，不替代前述代表性任务集和独立样本验收。若仍没有正式放行正例，只能发布受控评估版；不要求缺材料的当前案例强行放行。

按实施计划在第 4 日和第 10 个工作日检查源工程、探针与编译适配进展，再根据实际工作量排后续周期。检查点到期不等于产品已可用。

## 11. 验收以人工任务完成为中心

建议试点至少邀请三名未参与开发的地图工程师，经过统一简短培训后完成任务。人数和以下时间指标为本项目待实测的产品目标，不是行业标准。

- **任务完成**：已定义的常见修补任务均能通过页面完成；每个失败能定位、保存和继续，不能必须回到研发写脚本。量化记录独立完成率、研发介入次数、每路口人工分钟数、撤销返工次数。
- **几何结果**：手工修补改善对应实际问题；所有关联对象和交付范围复验，无未说明退步。14 份评分板及泛化集继续作为回归；保留新增未参与开发的数据作独立验收。
- **过程可靠**：来源不变、意图可追溯、一次事务可完整撤销、保存重开一致、过期预览不应用、取消/失败不丢已应用工作。
- **交互性能**：初步目标为选择/参数反馈 P95 ≤100 ms、拖动虚影 ≥30 fps；常用局部实际候选 P95 ≤5 s。复杂操作后台化并可取消，不假定整图检查可实时完成。M0/M1 固定测试机、样本规模和测量方法后校准目标。
- **交付一致**：同一候选在画布读回、质量报告和导出文件中一致；检查过期立即失效。允许的跨机数值差异及语义一致范围须在支持平台验证，不承诺任意机器逐字节一致。
- **操作范围透明**：首版保留源限速与 TOPO；推断信息和源修正有明显标识。未核验的 CRS、缺失的适用相位/台账证据仍阻断相应交付。

163 个路口仍值得做批量统计，但其作用调整为识别人工工具需求、首发支持边界和工作量；不以“先全部自动通过”作为开始交互产品的前置条件。

## 12. 首轮实施清单

按评审后的实施计划开工，先完成源工程与一种实际操作：

1. 固定证据与用例，用原始记录接口建立不依赖 XODR 的源项目。
2. 源页面/事务存储与一种边界修形的有界探针并行；先明确草稿和候选语义。
3. 接后台任务与已验证的编译适配器，再开放真实编辑操作。
4. 验证真实修补、失败工程保存与故障恢复，由独立工程师试用。
5. 按 WB-11 完成无 XODR 的人工接管，再逐项扩工具；正式交付材料从首周准备。

本次交付的是规划和交互示意，没有修改转换算法、评分门槛、旧研究证据或生产服务。后续开发在 `main` 接续；提交、推送按用户当次授权执行。
