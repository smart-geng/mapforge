## v0.4 当前执行入口：先保证编辑局部性，停止布局扫描

本节覆盖以下v0.3历史执行顺序。权威总方案仍为《地图格式转换工厂-首批三格式方案》v1.74及顶部补充；不另立转换平台。用户已批准静态地图与明确通行工况分开验收，见[验收决策v1](验收决策-静态地图与通行工况分离-v1.md)。本版不修改已有运行策略/门槛、原件、源限速或九处来源角色，不自动提交或替换8765/8766会话。

### A. 评审结论：问题是编辑契约缺失，不是尚未“统一求解”

1. **已有共同模型，不能再把共同模型当新成果。** L01五边界已共享54系数/24自由方向；更早的5父路/24转向状态也已建立。最近两布局都使s178目标点到位，却在s140.493776或s157.094467出现原件超限；原件平台布局使邻边2反向量增加0.404505m。这直接否定了“目标处变好即可应用”。
2. **整体最小形变不是局部性保证。** `outer_event_fairing.py`最小化全域形变，`outer_event.py`只硬锁事件外端/出生条件；没有将未选中边界及未编辑区间的整段几何固定。即使代价较小，求解器仍能用邻线位移满足另一处约束。
3. **移动结点不等于原形迁移。** `outer_event_layout.py`已测得两种布局投影差0.100143/0.066401m。它们是候选初值，不能作为用户未编辑时的新基准；此次零操作返回原XML的保护必须保留。
4. **旧Web有局部性但能力窄，研究核能力广但未形成可用编辑契约。** `RepairModel._build_handles/compile`仅允许7条内部共享边界的有限支撑位移；外缘和出生/消失事件锁定。不能直接把研究求解器挂到这些按钮上，或仅放开前端锁定标志。
5. **G2、拟合容差与形状自然是不同问题。** r6本身仍鼓包。相对r6曲率峰值、总变差、逐边界反向量“不增加”是研究护栏，不是合格地图的定义。不能默认为全局标准，也不能删除后把旧FAIL改成PASS。

### B. 本次只读检查：锁住邻线后，是否还“有东西可拖”

证据：`out/node4-edit-structure-review-20260915-r1/rank-review.json`；脚本`review_outer_edit_structure.py`。从原r6 XML恢复既有长曲线系数，在每个实际多项式区间约束未编辑部分的全部系数变化为零，不用抽样点冒充整段锁定。

- 五边界整体模型：24个自由方向。
- 仅允许边界3变化，其他边界在原事件全域保持原形：剩2个自由方向。
- 仅边界3的s163.6089–201.7074107（约38.10m、3个三次区间）可变：**剩0个自由方向**。
- 仅边界3的s157.6089–201.7074107（约44.10m、4区间）可变：剩1个自由方向。
- 同一个44.10m窗口明确选中边界3和4：剩2个自由方向，属于另一份范围声明，不能自动切换。

三组秩阈值结果一致，锁定多项式残差不超过约3.7e-16。以上只证明当前固定Line/C2三次表示中的线性编辑能力，**不证明目标位置满足宽度、来源、实际曲率等非线性约束**。

原因可直接解释：m个简单结点连接的C2三次区间有m+3个系数自由量；两端位置/一阶/二阶共6个独立条件后，通常仅余m−3。三个区间可能已无余量。鼠标能拖动不等于表示具有自由度；一个位置条件用尽唯一自由度后，不能继续承诺切向/曲率可独立调节。

### C. 路线裁决：保留现有内核，替换编辑变量的组织方式

**采用“原形可精确表示的局部控制空间＋共享边界派生车道＋可行性优先”的路线。** 不再枚举移动结点的近似投影，不继续扩整图自动求解，也不采购/移植一套通用CAD平台来掩盖来源和编译问题。

推荐实现形式是`x = x_reference + N_edit · u`：

- `x_reference`来自指定SHA的实际XML，只作编辑/撤销基准，不是好形状真值。
- `N_edit`同时满足原连续性/已批准事件条件和**未编辑几何的整区间零变化**。不是事后加一个“不退步”惩罚项，也不是前端单独画一条线。
- 选中一条共享边界后，相邻两车道的width与派生中心按边界差同步更新；**相邻车道的另一条物理边界不应自行漂移**。通行路径原件仍只读，不能偷换成新的几何中点。
- 若选择的编辑区涉及出生/消失约束、参考轴或口部，先返回必须关联的对象和作用域。用户确认关联范围后才建新意图，不能后台扩成整路口。
- `N_edit`为空或手柄在此空间无响应时，返回`EDIT_NO_DOF`。缺失自由度不是原件有错，也不是建议放宽源容差。

这与旧Web“叠加一个C2位移场”的区别不是换名字：旧Web只选已有内部断面且不负责修复坏基线；新模式先要求被编辑事件已能按原XML精确恢复、连续性成立，再按完整源身份和事件约束建立局部控制空间。已有断点不能靠叠加光滑场自动消除，必须转入独立的事件重建模式并通过准入。

**首个实现不移动、不增加结点。** 若实际能力检查证明所需局部模式不足，备选才是保持原形的有界长结点插入：必须先验零操作同形、简单结点/C2、最小跨度、复杂度和最终width展开。现有SciPy 1.15.3具备`BSpline.insert_knot`；这只是可用数学原语，不等于已批准加段或保证目标可行。本版不执行插结点、不新增拟合候选。[SciPy官方说明及Boehm 1980书目](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.BSpline.insert_knot.html)

### D. 约束重新分账，但本次不改运行门槛

后续每个约束必须记录`id / object_ids / interval / origin / role / policy_version / evidence`，`origin`区分规范、目标Profile、原件、用户意图、研究试验。缺来源的门槛不得自动成为发布标准。

1. **不可改的事实与边界**：原件/来源身份/CRS/原速度/已知TOPO、九处批准范围、phaseId规则。模型切分站位不等于原源点，不能为方便编辑改源点。
2. **产品和目标格式硬条件**：原各来源域容差、非碎段、正宽/合法零宽、正则坐标、实际边缘与接口连续、无非法自交/空洞、目标版本/Profile、范围外原形保持。0.75m只是当前L01局部门槛，不能覆盖其他原0.35m域或整个项目。
3. **用户编辑意图**：对象身份、明确作用域、期望点/方向、允许联动对象和冻结区。精确位置与近似吸附是不同模式；不在失败时把鼠标目标自动吸附到一个几乎没动的位置并称成功。
4. **形状改善目标与研究护栏**：平滑能量、到旧图的最小形变、r6曲率/变化率/总变差/反向量比较全部单列。未编辑区以原形等式直接保证，不靠这些总分替代；编辑区必须有完整形状意图和来源检查，不能仅命中一个点。若某个研究指标需要降为观察项，必须先版本化说明其来源和适用域，经明确评审后才改变运行策略；本次保留原护栏及旧失败。
5. **独立的动态交付门槛**：明确路径/速度工况及其批准、实际求值、域覆盖。源限速和旧压力失败保留，缺工况阻断最终交付，不阻断可独立进行的静态编辑。

ASAM将lane width定义为沿道路参考线站位的三次多项式；几何边界可由相邻width累积得到。换成任意NURBS/五次曲线后再密集采样写回，不是本方案的兼容解；当前目标仍按1.5M Profile/XSD，参考1.8.1说明不意味着升级输出版本。`border`也不自动解决可编辑性、来源和曲率问题，本轮不切换写法。[ASAM车道几何说明](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/11_lanes/11_06_lane_geometry.html)

### E. 先判可行，再优化；先实际XML，再应用

设计流程：`声明范围 → 原形/秩准入 → 共同约束可行性 → 编辑意图与形状改善 → 实际XML读回 → 预览确认 → 原子应用`。

- 原形、身份、作用域或控制能力不成立时，不启动求解器。
- 可行性阶段只寻找满足已登记硬条件的共同状态，不用形变收益抵消来源/宽度违规；失败区分固定表示不足、明确条件冲突和数值未收敛。

## 1. 结论与问题背景

采用 **统一道路约束模型 + 自动重建求解器 + 本地 Web 约束式编辑器**。不是在“全自动”和“全手工”之间二选一。自动求解负责多数正确输入，人工只表达局部修改意图、确认有争议的原始数据；两种入口必须调用同一计算和导出内核。

用户看到的弯折、洞、外缘不贴源图，至少涉及四类问题，不能统称“曲线不够平滑”：

| 问题 | 当前证据与原因 | 必须改变的机制 |
|---|---|---|
| 物理边界/车道延续错误 | 分合流时，通行 laneLink 不等于边界延续；曾把全宽继续车道误收零 | 物理边界图与通行图分开建模，源身份约束 |
| 参考线顺、边缘却过冲 | width/laneOffset 也是几何变量；强制横断面平直会锁死形状 | 左右边界、中心与参考轴共同优化，不独立补边 |
| 每段接上、整体不适合驾驶 | G2 不保证曲率变化率小；短区间仍可产生大 jerk | 在实际车道世界曲线及真实速度上约束，不只检查端点 |
| 路口填满却不是正确道路 | 通行路径并集、可铺路面、交通岛不是同一对象 | 道路面域单独表达；不以虚构 driving/restricted road 掩盖洞 |

现有方案已经写过“全局优化”，但 `joint_source_mouth.py` 等实际仍先解普通路、固定口部，再逐条解连接。某条转弯失败时，上游、下游、同口其他车道没有共享可调变量。改变求解器、增加种子或细分 width 不能代替这一结构性改造。

“全局”在此指 **变量、依赖关系和验收范围完整**，不宣称找到了非凸问题的数学全局最优解。优化器无解/迭代停止，只能说明该模型、该初值或该局部子问题未找到可行解。

## 2. 文献与成熟交互的可用部分

### 2.1 模型选择：不要按原始点逐段插值

Baran、Lehtinen、Popović，*Sketching Clothoid Splines Using Shortest Paths*，Computer Graphics Forum，2010，DOI `10.1111/j.1467-8659.2009.01635.x`：先构造 line/arc/clothoid 候选及可连接关系，再通过最短路径选择组合、最后约束拟合。用于本项目的**离散模型选择和复杂度惩罚**；不是直接移植绘画中的像素阈值、删角或裁点规则，也不是全局最优保证。[作者全文](https://users.aalto.fi/~lehtinj7/papers/clothoidsplines.pdf)

### 2.2 连续求解：把端状态、曲率、形状目标放在同一问题中

Bertolazzi、Frego，*Interpolating clothoid splines with curvature continuity*，2018，DOI `10.1002/mma.4700`：曲率连续回旋线样条的约束优化构造，可作为参考轴和连接曲线的数值基础。该论文不负责我们的多车道宽度、源身份、路面孔洞和导出语义，不能以“用了 clothoid”替代这些检查。[出版方](https://onlinelibrary.wiley.com/doi/abs/10.1002/mma.4700)

### 2.3 交互局部性：少量手柄，不是拖动每个测量点

Binninger、Sorkine-Hornung，*Smooth Interpolating Curves with Local Control and Monotone Alternating Curvature*，2022，DOI `10.1111/cgf.14600`：支持局部控制、G2 曲线和手动切向/曲率条件。借鉴其**手柄语义和有限影响域**；论文也说明局部优化可能随控制点位置产生不连续变化，不能据此承诺“一拖就稳定”。不将其输出未经编译验证直接当成 OpenDRIVE。[作者全文](https://alexandrebinninger.com/assets/publications/local_interpol_spline_mono_curvature/local_interpol_spline_mono_curvature.pdf)

### 2.4 防负宽：在构造时约束，不是导出后裁成正数

Allen、Kirby，*Bounds-constrained polynomial approximation using the Bernstein basis*，2021：Bernstein 控制系数的界可约束整个多项式区间，适合形成 width 的线性界约束。它是**充分条件而非必要条件**；控制系数界失败，不能据此声称所有正宽曲线都无解。[作者预印本](https://arxiv.org/abs/2104.11819)

### 2.5 可直接借鉴的操作方式

RoadRunner 的 Road Plan Tool 支持拖动控制点、调整曲率；移动共用端点会联动相邻道路，移动整路时区分拖动轮廓与松手后的道路网格。借鉴**联动编辑及预览/提交分离**，不要求采购，不把其能力当成本项目已实现。[官方操作说明](https://www.mathworks.com/help/roadrunner/ref/roadplantool.html)

### 2.6 验收对象是世界车道及边缘

ASAM OpenDRIVE 1.8.1 附录 D 的平滑要求覆盖可行驶车道内外缘以及 road/laneSection/junction 接口，不是只要求参考线平滑；其列举的可行驶类型包含 restricted，不能仅把辅助路标成 restricted 就认为免检。[ASAM 附录 D](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/16_annexes/smoothness_of_lanes/top_ter_smoothness_of_lanes.html)

以上为本次工程方法依据；当前写出仍遵守目标 Profile 与本地 1.5M XSD，不偷偷写入高版本元素。未引入论文附带代码；如需引入，单独核验版本、许可证及依赖链。没有哪一篇论文可以直接保证本项目全链路成功。

## 3. 统一数据模型：三张图、一个求解状态

```text
只读原件 + Profile/CRS + 原始身份/观测不确定性
                 ↓
物理边界图 ── 道路参考轴与共享断面 ── 通行拓扑图
                 │                       │
            可铺路面/交通岛图             │
                 └──── 联合求解状态 ──────┘
                       ↑              ↓
               手柄意图/锁定条件    同一编译器→XODR
                                      ↓
                       独立读回/来源/动力学/esmini
```

**Observation**：保留输入格式、文件 hash、要素 ID、点序、几何角色、单位、CRS 和可信度。MAP Lane.points 按车道中心观测处理，Link.points 不能替代它；SHP 中心和边界按字段映射后的真实角色处理。禁止用最近的另一条车道冒充同身份来源。

**BoundaryGraph**：一条物理边界一个对象，由相邻车道共享。出生/消失发生在已识别的结构事件，通行 TOPO 一分二不自动意味着外边界在该位置归零。

**MovementGraph**：原始连接与人工/default/full 推断连接分开标记；交叉口不同转弯轨迹相交是允许的，不能误当相邻车道边界自交。phaseId、region/node ID 不由几何求解器推断。

**SurfaceGraph**：表达铺面外环、明确交通岛/非道路孔洞、口部接触区和依据。没有证据的空白只能进入待确认对象。full/default 可以提议连接及路面，不得自动抹掉交通岛或把无法驾驶的填充带当可驾驶道路。

**SharedPort**：口部共享位置、朝向、曲率、断面边界位置及导数，所有相关道路只引用一个对象。禁止“各保存一份，再用容差拼上”。源停止线属于 Observation；结构 road 切分站位属于模型，二者不能混为同一个可拖端点。

**EditIntent**：独立的编辑约束层，不修改原件。普通贴合调整仍受来源容差约束；若用户明确纠正了错误原始数据，保存有依据的 override、旧值、新值、影响范围。原始来源差异仍显示，不能清除原有 FAIL 再称无损。

## 4. 求解方法：离散结构选择 + 连续联动优化

### 4.1 先选模型，而不是不停增加自由度

候选包括直线/圆弧/回旋线的少段组合、合适的参考轴位置、必要的分隔式车行道表达。基于连续源支持域建候选图，边仅允许符合方向、位置、曲率和复杂度约束的连接；选择少量可行模型后再连续优化。历史 Taubin/三回旋线求解器可以提供初值，不作为最终真值。

优先共享道路参考轴及左右展开；存在真实中央分隔、相向轴不适合共用或法线坐标折叠时允许双轴表达。**单边 lane 本身不等于违反 OpenDRIVE**，但不能为了省事把每条车道变成一条互相叠加的道路。分组由真实物理组织决定，不由渲染是否填满决定。

复杂度同时统计 reference primitive、width/laneOffset 独立控制量、laneSection、最小独立跨度和写出记录数。显示采样/验证加密不增加模型自由度；不把参考线碎片转移到 width，也不默认启用密集 paramPoly3 兜底。

**v1.47已实现的模型选择对照**：完整有序路径先试一条Line，不因为更复杂曲线少几厘米误差就给直道增加曲率。对单次横向分合流，另试“长直线—三回旋线—长直线”，保持两端直线切向/零曲率并限制额外反向转向。直线支持是可审计假设，尤其两点支持不能伪装成测绘真值。真实两处贴源但原速度仍失败，仅保留诊断，不能提升默认转换器。支持速度与形状约束分别展示，不以降低速度换PASS；单路径候选还必须编译成共享多车道模型才能谈交付。

### 4.2 连续变量必须包括整条依赖链

联合状态 `z` 至少包含：普通道路轴的少量参数、物理边界族系数、分合流事件站位（仅在源允许域内）、SharedPort、连接曲线参数、共享断面方向参数，以及用户手柄意图。

固定坐标基准，避免整个路网刚体漂移。全局求解可以用稀疏分块、消元、信赖域分步计算，但每轮必须重新检查跨块共享变量和完整受影响链，不能把前一块未经来源验证的导数当永久硬约束。

先满足下列硬条件，再比较拟合误差/曲率变化能量/与上一版的改动量；不能用加权平均“抵消”负宽或来源超限：

1. 同身份原始观测完整覆盖；双向中心/边界误差各自达标。raw via 单独统计，禁止被相邻长直线稀释。
2. 物理边界顺序正确，宽度非负；仅有明确生灭事件可为零。普通可行驶区间须满足 Profile 的有效宽度。
3. 法线坐标正则，`1-κt` 不折叠；曲线和条带无非法自交；不同转弯的合法交叉另判。
4. 最终世界中心及两侧边缘在内部和接口处位置/切向/曲率连续，不只 planView。
5. 在明确的目标速度下检查 `v²κ`、`v³dκ/ds_lane`，弧长必须是实际车道弧长。不得降速过关。源限速与设计验收速度不一致必须单独标出，不默认为已解决。
6. 保留已知通行 TOPO、车道属性和来源，不自动补 phase/改 ID/默认 CRS。
7. 满足消费端 Profile、少段及横断面复杂度预算。仍不满足时拒绝，不生成“勉强可用”正式件。

### 4.3 本轮已实现的一个关键子模型

旧 `flat_join_spline` 对 n 个参考原语固定 n+2 个三次横断面区间。每条边界有 `4(n+2)` 个系数，端部、C2 和接头零斜率条件恰好也是 `4(n+2)` 个方程：参考线和端状态固定后没有贴合自由度。

替代模型令参考曲率为 κ，横偏为 t，`A=1-κt>0`。在参考 κ′ 跳变处，所有边界共享：

```text
q = t′/(1-κt)             # 断面内各条世界轨迹的共同方向参数
[t″] = -q · t · [κ′]     # 补偿参考 κ′ 的变化；[] 表示右极限减左极限
```

保证 t/t′ 连续时，这组条件使两边缘及其任意固定比例内插轨迹的世界曲率连续；不必强行令 q=0。给定 q 后仍是小型线性系统；n−1 个 q 作为共享优化变量，而不是每个采样点一个控制量。n+2 区间数不变。实现 `mapforge/ops/shared_section.py`，有与旧模型等价、非零 q、全断面 G2、三边界和 Bernstein 变换测试。

这是**充分条件族**，并非所有合法道路的必要形态。固定参考的真实 A/B 已消除一处负宽并改善来源，但动力学仍失败；需要与参考轴和端状态继续联合，不能仅因此替换默认转换器。当前 width 最短仍可 3m，不能称已满足全部“非碎段”要求。

### 4.4 正宽和可行性诊断

三次 width 在物理区间上的 Bernstein 系数全部 ≥ 下界，可保证整个区间满足下界；同理可约束上界和边界顺序。求解阶段使用这一充分条件，独立验证仍求多项式导数根检查精确极值。若充分条件太保守，考虑同多项式的区间证书或模型选择，不偷偷增加拟合结点；用于证明的区间细分不进入导出。

失败报告区分：输入身份/结构冲突、坐标框架失效、几何可行但动力学失败、控制量不足、数值求解失败、消费端不支持。记录具体对象、原始点、约束残差与条件数。局部线性不可行证书只解释当前线性化，不能包装成原问题全局无解证书。

### 5.2 一次拖动的完整事务

1. 按下手柄：固定 `base_revision`，显示关联对象和锁定范围。
2. 拖动中：显示期望位置的虚影；可发送节流的预览请求。显示“未验证”，不能标 PASS。
3. 松手：后端按依赖图求受影响闭包，对同一几何模型进行约束投影，必要时建议扩大修改范围；不擅自越过锁定区。
4. 有可行解：显示**实际可实现位置**、来源最大偏差、曲率/jerk/最短跨度变化，允许应用；与鼠标期望不一致要可见。
5. 无可行解：保留上一版本，标红冲突对象，说明是源容差、宽度、锁定端、动力学还是段数限制。提供明确可选动作，不自动放宽约束。
6. 应用/导出：同一后端写临时 XODR→独立读回→检查受影响范围并重算整图必需门禁；同一 revision 的结果才可提交，旧任务返回不覆盖新修改。完整失败则回退或保存带 BLOCKED 的研究分支。

这能接近“所见即所得”，但不承诺“一改必满意”。空间不足、来源矛盾或高速急弯没有可行解时，产品应解释和保留选择权，而不是制作漂亮假路。

### 5.3 本地架构和数据契约

继续采用已定 **FastAPI + 本机浏览器**，只监听 127.0.0.1；首版原生 ES modules + Canvas/SVG 足以承载单路口矢量及手柄。第三方资源本地打包，不用 CDN，不上传私有地图。浏览器只绘制后端解析曲线的采样，不自行实现另一套拟合器；esmini 是异步独立消费验证。

后端复用转换器、门禁和原件读取，补齐 `ObservationSet / RoadConstraintGraph / EditIntent / CandidateRevision / ValidationBundle`。以下接口是**设计契约，尚未实现**：

```text
POST /projects/{id}/intents/preview       -> intent_seq, dirty_objects, ghost, constraints
POST /projects/{id}/intents/solve         -> job_id, base_revision
GET  /jobs/{id}                          -> lifecycle, candidate_revision, violation_details
POST /projects/{id}/revisions/{id}/apply  -> conflict or new_revision
POST /projects/{id}/revisions/{id}/export -> run_id, artifact_hash, validation_bundle
```

`EditIntent` 保存 source hash、坐标系、稳定 feature ID、手柄类型、作用区间、期望值、锁定条件、操作者/依据、base_revision。三轴状态保持 `运行生命周期 / 门禁 / 交付裁决`；对象八态另列。局部预览 PASS 不提升整图状态。

即使单机，也要校验 Host/Origin、会话令牌和 CSRF；限定已登记项目路径，防路径穿越和任意命令执行。保存原子化 run/revision；取消仅终止本次受控子进程。无需增加多租户系统。

前端拖动显示目标可为一帧级反馈；松手求解希望达到交互级延迟，**当前没有性能实测，不承诺毫秒级完整优化**。粗预览、严格求解、消费端验证可分层，但不可在状态上混为一次已验收结果。

## 6. 两条源路径的差异不能被统一 UI 掩盖

- **SHP**：中心+宽度或边界+左右关系两套 Profile 接入继续支持。真实 via/边界优先；手动修正不能将其悄悄改为端点推断。缺宽度按既定阶梯推导并标记来源。
- **MAP XML**：Lane.points 是车道中心采样，不能拿作道路外边界；不强制插值每个稀疏点制造波动。真实出口按原始关联使用；缺出口时仅同进口道路局部坐标下左右镜像，保留 INFERRED 标签。没有外边界真值时只能声明宽度/形状推断质量，不能宣称与真实 SHP 外缘等精度。
- **node18 的异常原点**：必须保留并指出；UI 可接受人工纠正提案，但未明确纠正前不自动删点。node4 MAP 跨源链疑点也不能用最近邻覆盖。

## 7. 实施顺序与交付标准

| 工作包 | 可验收产物 | 不能拿什么代替 |
|---|---|---|
| R0 基线与模型诊断 | 冻结输入/hash、完整来源、失败位置、自由度/条件诊断；本轮已做共享断面部分 | 只看历史 PASS 或截图 |
| R1 联动内核 | SharedPort 和 BoundaryGraph 成为真实公共变量；先参考线+横断面，再覆盖普通口部及所有关联转向；严格正宽/世界动力学 | 逐条成功后人工拼成“整图” |
| R2 整图几何闭环 | node4 全域来源、分合流、全部连接、路面外环、少段/横断面预算同时满足；SHP/MAP 均有独立完整结果 | 改限速、裁点、隐藏失败 road、增加碎段 |
| E0 真实编辑纵切 | 在 R1 同一内核上完成“载入真实源→拖一个边缘→联动相邻车道与连接→撤销→保存重开→导出→独立读回一致” | 仅动画、线框或仅保存 PNG |
| E1 工程编辑扩展 | 曲率/口部/锁定区/拓扑提案、差异与审计；超约束拒绝/恢复测试 | 任意拖动都显示绿 |
| R3 批次与推广 | 七路口双源 14 项实际跑批；明确异常输入阻断；普通道路、连接、铺面、原件完整性、消费端、CRS 各自裁决 | 把 1 个局部 PASS 宣称量产完成 |

R1 的正宽/G2 子模型和 E0 项目/编辑事务可以分别开发，**不需要等所有数学问题解决后才搭 UI**；但 E0 导出可用能力必须绑定已经验证的内核范围，未闭合对象继续 BLOCKED。优先完成一个真正的编辑纵切，不先铺开全部管理页面。

完成定义：固定真实原件，单次可重复运行得到同 hash 对应的完整来源报告、XODR 读回、动力学/形态门禁和亲自检查的截图；用户手动改动经同一路径重放可复现。已知输入错误单列需裁决，不要求算法“自动证明脏数据正确”。生产 CRS/数据授权等边界保持不变。

## 8. 当前明确不承诺的事项

不承诺非凸全局最优、不承诺任意拖动都有合法解、不承诺数据缺失时复原未知真实边缘、不承诺单个 G2 算法解决路网，不以 Web 应用取代自动转换器。当前没有已完成的编辑器，也没有已验收的全量平滑 XODR；后续交付按上表验证，而不是继续用版本号或单项测试数表示完成。
