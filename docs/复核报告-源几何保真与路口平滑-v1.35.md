# SHP / V2X MAP → OpenDRIVE 局部复核与修正

复核日期：2026-09-10。对应项目方案 v1.35。原始 SHP、MAP XML 未修改，工作树未提交。

> 同日后续重要更正：全车道动力学审计发现来源短支持免检漏洞，修正后正式14文件为8 PASS/6 FAIL；下文旧14/14通过属于历史口径。node18候选铺面已修复但动力学仍不合格，详见[最新补充](复核补充-口部铺面与全车道动力学-2026-09-10.md)。

## 结论与范围

用户指出的“部分位置不准、路口不平滑”包含真实实现问题。本轮修正了 MAP 横断面候选的误差度量、MAP 圆角端部方向、SHP 物理外缘约束与连接线候选选择。固定金凤样本的技术门禁和“所有源几何均已准确复原”是两个不同结论；后者尚未达到。

当前几何继续采用 line / arc / spiral 少段表达。可比的实测连接在严格误差域中按三、四、五段选择，段长下限 6m；未找到合格解时保留的三段 G2 推断连接是显式例外，其短段、来源偏差和端状态问题必须继续展示。不能把这些例外算成来源保真通过，也不能据此认定源地图错误。

## MAP 点的含义

- `Link.points` 是该方向 Link 的道路参考中心点列，不是整条双向道路中央分隔线。
- `Lane.points` 是各车道中心点列，不是车道边界。
- 当前参考线拟合消费前者；横断面和车道中心保真消费后者。二者分别叠画、分别计算误差，禁止混为一层。
- 缺出口按用户裁决，使用同一进口最终断面的左右镜像；有可匹配的邻居实测出口则采用实测。镜像出口及无实测路口连接均标为推断，不能宣称精确恢复缺失数据。

## 已修正的原因

| 问题 | 原因 | 修正与证据 |
| --- | --- | --- |
| MAP 平滑候选选得过弱 | 把不同采样间距的“点到点最近距离”当作几何误差，制造约半米的误差底噪 | 改为点到连续折线段投影，源点加密只用于测量；回归覆盖不同采样相位的同一曲线 |
| MAP 偏心路口圆角尖接 | 用“口部指向路口中心”的向量替代真实道路切线 | 从最终写出 width/laneOffset 求外缘位置、一阶/二阶导数及曲率；中心只用于决定正反方向，圆角使用实际外缘端状态；偏心十字口及变宽外缘回归已加入 |
| SHP node18 外缘被拉偏 | 为满足局部车道中心拟合，断面求解允许放松最外边界 | 真实物理外缘作为约束，禁止无依据调整总宽 |
| SHP node13 边界误差虚高 | 同一来源 ID 的下游续线超出本次目标支持范围 | 按共同纵向支持范围裁剪比较，范围外明确排除；同时保留不裁剪的局部差异图，防止隐藏尾段问题 |

## 仍未解决的重点

### 来源保真例外不能由技术 PASS 掩盖

SHP 共 189 条连接路中，正式版仍有 30 条 `minimal-chain-source-fidelity-unmet`。本轮初始还记录了 52 条 `source-end-state-conflict`，经代码复查发现其判据用的是 7m 弦方向而非端点切线，正常弯道也会触发。现已将这些成功拟合项恢复到完整 G8 验收（未放宽门限），弦方向差仅保留为诊断；14 文件重新生成、G1–G11 与 esmini 均通过。

另加了不采用 eligibility 过滤、不裁剪原始 via 的复核：原始完整线对比 laneLink 确定的“进口末段 30m→连接路→出口首段 30m”。**189 条原始 via 的前后端点均在 1cm 内闭合，但正式版有 59 条超过 P95≤0.75m / max≤1.50m 的本轮复核线。** 该口径比单独比较 connecting road 更公平：原始 via 延伸进普通 road 的部分也参加行车链比较，不能把合理分段误判成缺失（仅与 connecting road 比较时会误报为 95 条）。结果见 `out/unclipped-via-audit-v135.json`，包含逐文件 SHA256、两种距离及每条源 ID。59 条包含部分仍通过较宽 G8 的曲线，不等同于 59 条拓扑错误。

最短例子是 node18 road135 / 源车道 `2024010516410808896`：

- 当前 G2 推断连接总长 8.674m，三段 2.647 / 3.381 / 2.647m，最大曲率约 0.399/m。
- 源曲线原长约 15.743m；当前口部支持裁剪后只剩约 5.249m。
- 上述裁后源线到当前两端口部的位置差约 4.295m / 3.676m，弦方向差约 55.74° / 56.01°；这不是原始完整几何的端点误差。
- 原件复核：via 与进口 `2023061414495404821`、出口 `2023061413202092400` 的端点距离都是 **0.0m**。未裁剪 via 的端点与 written mouth 相差 **9.229m / 5.214m**。因此当前共同口部建模是重要原因，不能归咎于源拓扑断开。
- 速度上限只约束平面横向加速度/jerk 代理。它不证明某车型的最大转角、最小转弯半径或扫掠包络可行，不能把降低速度当作自动驾驶可行性的充分证据。

### 已实施的隔离候选：来源包络入口与真实车道尾段

`build_junction_xodr(..., mouth_policy="source-envelope-candidate", mouth_margin_m=8)` 是未提升到默认路径的试验入口：共同口部放到最早真实车道端点之前；真实 TOPO 的 incoming→via→outgoing 联合用于少段拟合。端点不闭合时不虚构直线补齐。三至五段曲线、每段≥6m 的约束不变；普通 Link 的语义分段不等于 planView 几何段，不能混用长度阈值。

- node18 3m 预留试验：36 条组合来源，1 条拟合 fallback、2 条未裁剪复核超线。
- node18 8m 预留试验：36 条组合来源，**0 fallback、36/36 未裁剪复核通过**。这只是该路口的候选结果，8m 尚不是通用标定值。
- road135：三段 **15.340 / 7.761 / 8.388m**；完整原始 via 到目标 P95 **0.398m**、max **0.486m**，不靠碎段。此时 XODR 连接路包含两侧真实尾段，所以新口部在原始 via 端点外约 8m 是表示边界移动，不是道路横向偏移。
- esmini RoadManager：36 对接缝、显示 0.0cm，21 次有效穿越、0 跳变；9 次灭车道并线单列。G11 PASS、65 个 warning。车型转角和扫掠包络仍未验证。
- **尚不可提升**：前移入口后的源边界尾带与原 INTERSECTION 面并集为 MultiPolygon；生成器拒绝取凸包/仅取外圈偷偷填掉岛或真空隙，候选 G9 的 leg/paving overlap 仍为 0。连接曲线改善不等于铺面问题已解决。
- node4 的 3m 候选也已生成（24 条组合来源、1 fallback），同样存在铺面重建待办。最初的拦截是把 6m 几何下限误套到剩余 Link span（实际还剩约 4.6m），已修正；不是已确认的源 Link 跨越。

下一步应先重建“前移入口后的路口物理面、中央岛及各车道尾带”的带孔区域与来源映射，保持普通路/连接路接缝和原始边界；再对其他五个路口做入口位置受约束选择。不得直接将 8m 常量推广、降低 G9 门限或用铺面视觉掩盖路由问题。

规范依据：[ASAM connecting roads](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/12_junctions/12_04_connecting_roads.html) 要求连接车道平顺衔接；[lane linkage](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/11_lanes/11_05_lane_link.html) 要求真实物理端部相连。入口前移加来源尾段是本项目据此提出的建模方案，并非规范规定的唯一算法；输出仍为 1.5，不引入 1.8 专属属性。

### 路口可见边缘与可行驶路径要分别验收

SHP 路口面来自原始多边形，MAP 路口面来自口部推断。铺面只是可见路面，不参与寻路；真正可行驶连接由 connecting road/laneLink 承担。G9 检查连通和孔洞，G10/G11 检查连续与几何指标，但截图中局部外轮廓仍须检查。G2 角点构造正确也不自动保证写出后的双轴铺面并集处处满足曲率连续。

绝对 CRS 仍未通过外部控制点核验；卫星底图用于发现形态问题，不能据影像观感宣称厘米级绝对定位。生产交付的 CRS 阻断与上述几何问题分别记录。
