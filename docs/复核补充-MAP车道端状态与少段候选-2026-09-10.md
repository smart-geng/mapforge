# MAP 车道端状态、少段参考线与联合横断面候选

2026-09-10，方案 v1.36。目标仍未完成；本记录区分代码修复、隔离候选、正式输出与视觉验收。

## 1. 这轮确认并修复的原因

1. **路口连接瞄准的航向不对。** 旧 MAP 连接器用参考线航向及常偏移公式 `κ/(1−tκ)`，漏掉车道宽度和 laneOffset 的一、二阶导数。位置接上不代表切向接上。对正式七份 MAP 文件重新检查，最大航向缝为 node16 的 **4.218°**；node3 为 0.948°。这不是查看器误差。
2. **参考线 G2 不足以保证变宽车道 G2。** 三段回旋线的曲率变化率在段端变化，叠加非零横向导数后，实际车道中心可能出现曲率跳变。node3 原四条普通 road 均存在此问题；同一保真约束内，单段圆弧/回旋线已足够，不必先采用三段。
3. **图上的“点”不能混为一谈。** `Link.points` 是方向道路参考中心观测；`Lane.points` 是车道中心观测，不是物理边界。新联合求解直接约束两个相邻边界的中点，不把 MAP 点冒充 SHP 边界。缺实测出口时严格保持 `left_i(s)=2*inner(s)−right_i(s)` 的同 leg 左右镜像。
4. **诊断图曾漏掉两个真实 ID。** node13 文件内主节点是 `(21901,21901)`；node16 是 `(500,21801)`。旧局部叠图按文件名数字找节点，导致这两份的 Link 参考点数量为零。现在从 manifest 的 main 身份读取，缺失必须报错，不能报告空集“零误差”。

已接入正常 MAP 生成代码的是第 1 项：`map_to_xodr._written_lane_end` 从最终写出模型计算车道端点、实际切向、实际曲率，data/default/full 连接共用。单段优先与整路联合求解目前仍在 **spikes 隔离试验**，尚未提升为全部输入的默认算法。

## 2. 验证不能只查道路内部

G11-C 新增每个显式 junction laneLink 的入口和出口检查，采用最终文件中的真实 lane ID、contactPoint、width/border/offset 与行车方向。门限为位置 1cm、航向 0.1°、曲率 `1e-7 /m`。找不到引用车道/不支持的几何必须失败，不按最近车道替代。

独立验证 `scripts/esmini_lane_interfaces.py` 不调用 mapforge 的车道求值器：从 esminiRMLib 读取世界 XY，在端点内侧分别以 2cm、1cm 间距取样，估计切向与曲率并检查收敛。数值估计曲率差门限为 `1e-6 /m`，区别于解析门禁；不把 esmini 的参考线 heading 字段当作车道切向。它只覆盖一段 laneSection 的连接路，遇到不支持的结构报错。

**正式输出未覆盖，其最新 G11 为 0/14 PASS。** 原先仅 NODE5 的 PASS 也被跨道路航向检查否定。七份 SHP 和七份 MAP 的质量报告、G11 与交付裁决已重算，全部 BLOCKED。证据：`out/g11-road-interfaces-v135.json`、`out/road-interface-baseline-v135.json`。文件名 v135 表示被复核的旧资产，不是当前方案版本。旧 `closed-loop-report.json` 不是本轮全量结果。
