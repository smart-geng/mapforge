# MAP 铺面斜切与车道边缘接头复核

2026-09-10，方案 v1.37。四份 MAP 的明显斜切角、铺面台阶已有可视改进，但严格车道边缘接触条件仍未通过。**目标没有完成，候选不是自动驾驶可交付地图。**

## 1. 两个已定位的生成错误

### 铺面把不相连区间连成了路面

旧 `add_paving_road` 沿两个轴切路口多边形，对一条切线上的所有交集直接取 min/max。当交集包含不相连区间时，这等价于把中间空白也填入。它不是渲染精度问题；即使无限加密采样，仍会导出错误面域。

node16 的 G2 推断圆角本来是弯的，实际导出却多铺约 33㎡，形成西北、东南两块斜角。`scripts/map_paving_audit.py` 将解析圆角、全部最终路面、超出/未覆盖区域同时画出。这里的目标轮廓是 **INFERRED**，并非 MAP 提供了实测路缘。

隔离候选 `spikes/map_corner_surface.py` 改为保留每个圆角的三段解析回旋线，用向内的曲线带覆盖外缘，内部用经过包含性检查的中央多边形及口部三角面覆盖。不取全路口凸包、不裁掉源点、不加密成米级宽度拟合链；候选出现越界、孔洞、不连通或口部无重叠时拒绝，失败不修改输入。

此法尚未提升为默认铺面算法。四个四腿路口各用10条辅助road：4条圆角带各3个spiral，6条内部三角面各1个line；每条只有1个laneSection，宽度分别1条/2条记录。三角面内部边不属于真实路缘，也不属于行驶轨迹。其restricted标签不保证所有消费者禁止车辆进入，仍只能用于受控仿真展示。

### 连接路使用名义宽度，而不是最终车道宽度

旧 MAP 连接路统一写3.5m，实际连接的拟合车道在 node16 有2.261m、2.674m、3.913m等宽度。中心接上了，路面仍会外冒。

`mapforge/ops/connector_width.py` 已接入正常MAP生成：读取所连接车道最终section、width/border及真实lane ID，分别取得入口、出口宽度。采用固定三跨度、单调C2的宽度过渡，端点一/二阶导数为零；laneOffset始终取宽度的一半，因而行驶中心线保持不变。三个多项式完全由两端宽度和整条长度确定，没有逐采样点的自由控制量；本轮四份候选最短过渡跨度为5.782m。相等宽度只保留一个常数记录。

中途单三次过渡虽能消除宽度错位，却引入端部边缘曲率跳变，已否定并换成C2版本。这个C2规则仍没有匹配任意来源边缘导数，不能称为整个车道的G2接续。

## 3. 为什么仍然阻断交付

ASAM的接触点定义覆盖车道内外缘，不只车道中心；平滑检查还涉及laneOffset、width/border和道路、车道、junction连接。restricted也在其列举的可行驶类型内，不能用标签免除一般规范要求。[ASAM OpenDRIVE 1.8.1 Annex D](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/16_annexes/smoothness_of_lanes/top_ter_smoothness_of_lanes.html)

新`validate/junction_edges.py`对每条显式连接的左右边缘分别计算世界位置、切向和曲率。暂支持单laneSection、contactPoint=start的连接路；不支持/缺引用则失败，绝不默默跳过。工程检查线为位置1cm、航向0.1°、曲率差1e-7/m，后者是项目G2要求，不是声称ASAM规定该数值。

四份候选的中心线接头通过，但边缘仍有3.9～14.7cm位置差、0.305～1.622°切向差，故 **G11-edge-contacts全部FAIL**。原因是连接参考线朝向最终车道中心切向，而普通道路断面仍垂直于其自身参考线；两者不一致时，等宽也不代表两端边缘重合。宽度C2不能消除此坐标架差异。

该附加门禁已进入`finalize_opendrive_g8`和CLI交付裁决，必需项现在为G8、G11、G11-edge-contacts。输出`.edge-contacts.json`，检查异常也阻断。所有四份候选保持BLOCKED，并另列`candidate_not_promoted`和`sim_auxiliary_only_not_ad_strict`。

正式旧14份已只重算质量和交付报告，G11仍0/14通过，边缘接头也全部失败；XODR哈希逐一确认未变。汇总`out/g11-edge-contacts-v137.json`。旧“G1–G11全绿”不代表新增接触条件已满足。

## 4. 验证范围及后续

- 最新48项测试通过（143.57s），包含真实MAP node4/node16及多节点实测出口、最终宽度、固定C2过渡、边缘故障注入、铺面失败原子性、G8/G11及交付阻断。不是全仓/SHP全量测试。
- 本轮没有修复SHP生成几何；其前一轮node4严格G11回归失败仍在，其他SHP尚未整图达标。MAP node4/node17/node18的少段整路候选也仍未完成。
- esmini的102项证明的是世界XY中心位置/切向/曲率消费，不是车辆控制器闭环。其地理参考属性警告仍在，绝对CRS仍未核验。
- 下一步必须把普通道路口部与连接路的参考线方向、中心偏移、宽度及两侧边缘端状态联合求解，不能再只钉中心线或追加局部碎段。先用新增边缘故障用例验证，再做MAP四份及SHP真实复测。
- 新铺面算法目前仍为spike，需覆盖其他路口/实测出口/不同腿数后再决定提升。自动驾驶严格Profile不得把辅助铺面作为可行驶补全。
