# 完整源路径少原语与直线保护复核

> 2026-09-11 · v1.47。**这是算法原型和真实路径对照，不是修好的XODR。** 没有覆盖正式输出，没有改原件、限速或验收阈值；SHP整图、MAP和Web编辑器仍未完成。

## 1. 为什么做这一轮

v1.46查出了两类问题：旧普通路口部本身偏源，且固定直线参考轴、长跨度三次边界族在两处分合流无法同时满足来源/C2要求。不能据此认定数据错误或全局无解，也不能继续只换小段长度。

本轮直接从同身份LANE_LINK及明确laneLink读完整有序路径，测试**另一类模型**：1/3/5段回旋线，长度自由、曲率结点共享，不沿用旧width样条的导数条件。观察到自由回旋线即使几何误差较小，也会在原本近直的区间产生额外波浪。因此增加“Line优先”和“两端长直线保护”候选，不能仅凭G2或误差合格选择曲线。

这里的LANE_LINK是原始**路径观测**；特别在零宽分支附近，不默认它就是边界几何中点。单条路径结果不得冒充多车道参考轴、width、laneOffset和junction的整体结果。

## 2. 文献如何落实

- Bertolazzi/Frego的曲率连续回旋线样条工作提供约束优化的基础；本原型用共享曲率结点构造G2，再检查曲率及其变化率。**采用回旋线不自动保证动力学合格。** [论文出版方](https://onlinelibrary.wiley.com/doi/abs/10.1002/mma.4700)
- Cudrano等2022年的 *Clothoid-Based Lane-Level High-Definition Maps: Unifying Sensing and Control Models* 将线标记参数及连续性联系组织成优化图，再压缩不必要原语。借鉴其联合模型和压缩思路；论文结果是G1标记样条，不能当作本项目G2、多车道正宽或XODR验收证明。本轮未复制其实现，也未引入g2o。[IEEE期刊文章](https://read.nxtbook.com/ieee/vehicular_technology/vehiculartechnology_dec_2022/clothoid_based_lane_level_hig.html)
- 专家意见中的“先满足硬条件，再减少原语”“禁止无理由反弯”“计算候选支持速度”已落实为不同模型的对照及拒绝规则。自由3段的速度诊断结果有波浪，不作为保护直线的替代方案。

本轮测试的单段最短5m、直线支持至少20m、分类残差8cm、切口可移动范围等均为**明确记录的模型选择参数**，不是ASAM通用条款，也不证明这一候选族之外无解。

## 3. 新代码与边界

- `spikes/sparse_path_model.py`：先验证一条完整TLS Line；不合格再测试少量G2回旋线。保留原始顶点、起终端覆盖，禁止回头；只求解有限原语数，无碎段兜底。
- `spikes/straight_transition_model.py`：`Line + 3 Spiral + Line`，四个几何变量为两端直线切口站位及法向平移。直线曲率严格为0，接头G2，解析航向包络限制额外反向转向。不能处理任意多弯/任意拓扑；两点确定的直线只标记“模型假设”，不是实测直线认证。
- `scripts/sparse_source_path_trial.py`：原件身份/方向/完整路径提取、文件hash、原始几何快照和参数报告；始终BLOCKED，退出2，不写XODR。
- `scripts/review_sparse_paths.py`：重新读取当前原始SHP核对身份及全部路径点，读回试验参数复算，**不运行优化器、不继承旧PASS**。仍使用同一数值几何库，不是独立esmini消费端验证。

来源距离不再只依赖有限点PASS：对来源折线和解析曲线按各自弧长覆盖，以距离函数的1-Lipschitz性质给出`最大采样距离 + 间距/2 + 数值余量`上界。必要时细化**验证采样**，不增加拟合或导出参数。该证据针对“给定的原始折线”，不是稀疏采样间未知真实道路的误差证明；Distance仍依赖数值实现。

速度诊断仅改变优化目标，不改变最终验收速度：`verify`总是按原始60km/h复核。所报支持速度是当前曲线的恒速平面指标 `min(sqrt(ay_limit/max|κ|), cbrt(jerk_limit/max|κ′|))`，不是限速建议、全局最优速度或车辆实测安全速度。
