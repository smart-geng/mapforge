# 弯曲参考轴与可写出三次边界：实现及真实复核

> v1.60 · 2026-09-11。**仍未得到新的合格XODR，目标未完成。** 本轮是J1/J2内核推进，不是整图交付；原件、速度、角色批准范围、MAP宽度门禁均不改变。未commit。

## 1. 背景与本轮范围

v1.59的五次研究边界在0.35m来源预算内有改善，但原60km/h动态仍失败，而且不能直接写成OpenDRIVE三次width。继续把五次结果细分近似，会重复使用误差预算并违反用户的少段要求。

本轮直接构造**一个解析Line/Arc参考轴＋共享长三次物理边界**。仍使用node4北侧25源车道、33原边界和11物理边界族，不从旧XODR复制目标形状。旧参考线只提供初始坐标框架；源端点及源分合流接触随每次参考轴变化重新投影。

这是可精确换算为三次幂基的表示内核，**不等于完整道路编译器**。原源端域/两条通行观测路径/全部关联连接尚未闭合，故没有编造laneSection映射或导出残图。

## 2. 已实现的机制

- `mapforge/ops/arc_source_chart.py`：解析Line/Arc世界坐标、稳定逆投影、源原始线段与参考轴法线的精确交点。不把弯曲坐标系中的源段误当成直线，也不对折返源排序删点。
- `spikes/arc_source_boundary.py`：原物理接触共享C2；统一全局分界，所有相邻边界在同一长区间表达。源端部斜切导致区间过短时，统一删去多余内部分界以延长区间；必要事件不能删除，没有短段兜底。
- 原三次B样条到`a,b,c,d`是代数换基，已用独立多项式求值验证，不以密集采样拟合代替编译。宽度非负/参考轴正规性保持整区间约束。
- `shared_boundary_dynamics.py`支持圆弧参考轴下真实中点曲率及曲率弧长导数；使用完整世界公式，复数步长Jacobian与独立差分对拍，未用小角度近似。当前真实模型没通过来源检查，因此**真实60km/h动态本轮没有运行**。
- `scripts/fit_arc_source_block.py --optimize-axis`以连续航向/曲率为外层变量、全部共享三次系数为内层变量，重建每个轴状态下的来源约束。不是只挑三个固定角度；但仍是有界局部变量投影，**不是完整参考线/事件/全部连接的全局求解**。
- 原始顶点顺序映射单独保留：坐标图允许整体反向排列时，诊断索引仍指回原件顶点，不冒充原始顺序。

### 同一个误差预算

源折线段在圆弧坐标图中一般是非多项式。设源线法向为N，参考轴位置、切向、法向为r/e/n，则：

```text
t(s) = N·(P-r(s)) / (N·n(s))
q = (N·e)/(N·n)
t'' = -k(1-kt)(1+2q²)
```

通过单位标架的Lipschitz界约束分母远离零，得到每个检查区间的二阶导界M2。源曲线与其区间弦的误差不超过`M2*h²/8`，从原0.35m预算中扣除，再对三次目标与弦的差作Bernstein约束。因此没有第二笔“编译允许误差”。2m证书区间和0.5m独立检查点**均不成为曲线分界或XODR记录**。

单测中，100m原直线在弯曲坐标图中只连两端会产生超过1m的中部误差；新整段证书检测到该误差。另有正负曲率、接近零曲率、非正规/折返、所有共享分界、拒绝状态禁止换基、梯度等测试。

## 3. 真实结果：表示受限仍未解决

最终证据目录：`out/shp-arc-source-v160-reproducible/`。运行文件名不是验收状态；以`report.json`的`RESEARCH_ONLY_NOT_MAP`为准。

连续轴搜索作24次函数求值，缓存后22个不同轴状态；21个来源模型拒绝，1个线性求解数值错误。数值错误不当成几何无解，也不进入最佳候选。搜索触及计算预算，未收敛；没有全局最优/无解结论。

各状态只有一个参考原语，边界变量66或74个；所有独立区间至少15.10879m。已访问状态中的最小完整模型额外统一松弛为0.77261046m，轴参数为航向增量0.00140625rad、曲率−0.002765625/m。它是**被拒绝模型的约束松弛量，不是合格地图误差**，也不批准放宽0.35m。

|---|---:|---:|

这说明“原顶点贴合”不能代表源形状恢复。最佳已访问Arc状态的独立检查包含5310个原边界/中心见证和1169个宽度见证，没有使用来源插值包络余量；原始残差8.50e-8、对偶残差4.54e-15、间隙1.82e-13。冲突不能仅归因于Bernstein包络过保守，但仍只针对该参考轴、基底和接触条件。

主要来源见证落在北侧分合流附近的边界`2023081117231582445`、`2023081117185599268`、`2023081117231580454`等。参考轴改变共同弯曲，仍未充分表达这些边界之间的相对展宽形状。不能据此声称SHP本身错误或所有OpenDRIVE表示无解。

## 5. 文献与标准对应

- ASAM OpenDRIVE的Arc是恒曲率解析参考线，width是沿参考弧长的三次多项式。本轮直接使用这一表达结构，不将五次系数塞进width。[ASAM 1.7几何与车道定义](https://www.asam.net/fileadmin/Standards/OpenDRIVE/ASAM_OpenDRIVE_BS_V1-7-0.html)、[Arc条款](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/09_geometries/09_05_arc.html)。查看较新条款不改变项目目标输出版本。
- ASAM说明paramPoly3的参数与实际弧长一般是非线性关系。因此不把任意三次参数直接当s来写宽度，后续若引入该参考原语必须处理弧长映射。[paramPoly3条款](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/09_geometries/09_06_param_poly3.html)。
- Eisemann/Maucher的点云生成OpenDRIVE研究用于确认真实地图评价场景，未从摘要推断其算法能保证本项目分合流/动态目标，也未复用代码。[作者预印本](https://arxiv.org/abs/2405.07544)。

## 6. 后续工作，不继续把单Arc当万能模型

1. 根据来源见证研究**相对展宽/事件的约束**，与参考轴共同弯曲分开；补齐完整中心端域与物理边界链间的动态覆盖，避免极短未检查区成为自由度漏洞。
2. 继续可写出的少原语参考轴、世界G2共享断面、源支持内合法事件和全部入射连接的同状态求解。若扩大到长spiral或改变合法分界，必须重新证明源预算与全边缘连续性，不能直接照搬本轮恒曲率的横向C2规则。
3. 不能以新增几十个Arc角度搜索、删除原段约束、降低速度或放宽来源误差代替结构重建。当前局部搜索不是一般模型的无解证明。
4. MAP待确认的名义宽解释继续保留原门禁，不把自动续跑当批准；用户已确认的node4两处SHP角色不重复索要。
