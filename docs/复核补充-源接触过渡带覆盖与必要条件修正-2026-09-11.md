# 源接触过渡带覆盖与必要条件修正

> 2026-09-11 · 对应方案v1.61。研究实现及历史参数复核，不是新地图交付。

## 1. 本轮结论

修复SHP共享边界模型的一个检查漏洞：左右原边界的记录切点不在同一断面，只逐条取左右共同范围，会漏掉相邻记录之间的过渡带。原TOPO证明这些车道连续；检查不能在这里中断。

真实node4北侧范围的18个普通延续事件，对应18处遗漏检查带，按车道累计1.584826813m，最长0.389847304m。累计值不是道路纵向长度，也不是新增道路长度。源25车道、33边界、11长族均保留，**新增几何段和几何变量均为0**。

修正v1.59的后续判断：其旧自由站值/导数状态在原18929条约束中仍满足数值容差，但在新增882条约束中有210项超过1e-6。补齐后，连不限制样条基底的必要条件模型也出现数值冲突。因此，不能继续据旧结果认为“只要换样条基底就能满足当前条件”。这仍不是SHP错误或所有OpenDRIVE表示无解的证明。

实际历史长曲线仍失败。没有新XODR、没有本轮esmini成果、没有放宽来源容差或降低速度；旧v1.45地图没有覆盖。

## 2. 代码如何修复，不用细小段填空

- `mapforge/ops/source_transition_domains.py`依据原TOPO、原边界左右关系及已证明物理延续构造检查区间。只在来源支持的唯一长边界族上取值，不按距离猜车道、不外推、不添加laneLink。
- `SourceBoundaryBlock`与`ArcSourceBoundaryBlock`将这些区间纳入相同共享系数的非负宽约束；`midpoint_rows`使联合动力学优化覆盖它们；2cm复算检查同一物理车道中线的曲率和曲率变化率。
- 原记录索引和原始顶点序号保留。Arc图中从原坐标重新投影，不能照搬Line站位。左右接触身份、站位或速度依据不一致时明确拒绝。
- 两个已批准零宽生长事件不是普通通行延续，不自动补成普通laneLink。相关物理车道中线原检查仍保留，独立movement观测路径验收仍未完成。
- 自由站值必要检查的过渡带导数上界使用两侧已证明连续的长来源上下文，不仅用几厘米检查带加0.35m误差来估算。后者会给出过松的航向上界。
- 不静默跨越不同来源速度。当前真实18处均为原60km/h；若两端速度不同，需要有来源支持的速度边界模型，当前分支拒绝猜测。

`1e-8m`仅为浮点站位数值分辨阈值，不是允许增加短道路的阈值。源端部仍有14条中心支持缺口，不能把普通接触带补检称为整图覆盖完成。

## 6. 对后续路线的约束
