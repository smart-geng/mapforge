## 2. 实际实现

### 2.1 连续参考轴和完整来源重投影

`spikes/joint_corridor_connectors.py --rotating-axes`（由重建脚本选项传入）将每条普通道路的Line方向作为一个连续变量，围绕原路口端旋转，范围为种子方向±3°。NODE5联合状态334变量：275共享边界系数、4轴角度、11条三回旋线连接的55参数。口部世界位置、方向、曲率与全部依赖连接同时重算；未增加planView原语或逐原点几何结点。

`spikes/rotating_source_tube.py`每次改轴重投影全部同身份原点、原段和端部，保留原点序号；完整段误差用每个Bernstein见证约束，不只取几个采样值。2m划分是证书检查单元，不是输出曲线段。旋转后超出参考路端部的原点仍做完整世界距离检查，不能靠裁掉远端通过。

当前只支持无objects/signals/elevation/superelevation的单Line普通道路；这些附属对象未实现重投影，因此遇到就拒绝。laneSection事件站位、长基底与端部构造仍固定，尚非一般参考轴/事件/车道角色全局求解。端口世界边缘与中心一起联动，不能将“参考轴可旋转”误称整图已解决。

### 2.2 修复真正的导数问题

早期实现先把一个区间多个源误差压成最大值，再分别求边界系数和角度导数。在多个见证并列最差时，两类导数可能选到不同见证，得到不存在的联合梯度。直线仅换坐标、物理曲线不动的反例曾产生168.946808的归一化方向导数差。

修复为保留全部见证，解析计算投影站位、截断区间端点、弦斜率和Bernstein项的角度导数；新增坐标变换不变性、反向原点编号、区间鼓包、端部裁切及独立差分负测。不能把这类实现错误全归于优化器或源数据。

可行性恢复保持硬来源约束；线性化残差接近零时采用按尺度的最小改动法向步骤，再检查真实非线性约束并回溯。普通平顺QP仍保留。没有实现二阶校正求解器，也没有引入新的优化库。

### 2.3 显式宽度不再只作弱目标

`mapforge/validate/map_width.py`从原XML独立读取laneWidth，以来源身份关联写出车道，在原Lane.points支持内求每条三次width的解析极值（包括内部导数根、宽度记录接头），不靠稀疏采样找最大误差。缺字段保持缺失，不把默认3.5m变成源事实；重复冲突、覆盖缺失和不支持的坐标图不判PASS。

当前保守合同为`map-explicit-constant-width-v1`：没有经确认的变宽解释时，原显式标量在原点支持范围内按常宽保留，1e-6m仅是数值容差，**不是宣称MAP标准保证全域等宽或测绘精度达到微米**。它防止优化器未经记录就用大幅缩宽换取可行。单一标量不能提供逐站位真实边界；以后若引入名义宽度/渐变解释，必须版本化并保留差异，不能静默把本次失败改成PASS。

还需区分宽度度量：本审计比较的是写出OpenDRIVE的t向width，尚非沿实际车道中心法向求交所得的物理净宽。在偏离车道走向的参考轴上，二者不能直接等同；因此常宽合同的失败不能证明所有保持物理宽度的参考轴模型都失败。下一步需要把参考轴度量变换也纳入，而不是拿常宽等式替代来源语义核查。

`spikes/road_boundary_family.py`将显式宽度加入长多项式跨度的精确等式；旋转支持范围内另加非线性宽度约束。所有普通道路先初始化、再进入全连接联合求解的现有次序仍在，因此初始化拒绝不代表连续自由轴的完整模型无解。

`mapforge/report/decision.py`新增必需门禁`MAP-explicit-width`及`.source-width.json`，FAIL或UNAVAILABLE会阻断MAP交付。来源中心、CRS、G8/G11通过不能绕开它。当前几何宽度审计只支持单Line坐标图，其他情况明确UNAVAILABLE，不能声称默认任意MAP路径都已能验收。SHP门禁不因此改变。

## 4. 进一步定位：原点事实与点间连线必须区分

新增只读`map_width_model_probe.py`，在相同长基底、固定轴、显式宽度和结构下比较四个问题：完整折线/仅原始顶点，各自再比较固定口部导数/自由口部。放松后的参数不返回给编译器，完全不写XODR。

当前报告：`out/map-width-model-v157-final-{NODE5,node16,node13}/report.json`。

- NODE5、node16全部普通道路：仅保留原始顶点的线性模型均可行；失败出现在把原点之间的整条弦线也作为严格来源包络之后。
- node13 road13同类；road12即使仅原点仍拒绝，固定口部phase1.223843、自由口部0.698693。不能以放开一个端点就宣称问题解决。
- node13南侧原lane2第5点、lane3第3点（**0起始索引**）在当前轴投影站位仅差0.040522m，横距4.349600m，而按两条3.5m车道共享边界堆叠应为3.5m。它们不严格共断面，因此这只是可定位的冲突线索，不是无条件的原数据错误证明。

这批反事实说明应检查**离散观测、点间不确定性、常宽解释和结构事件的联合模型**，而不是继续调单连接、强制压窄、删除原点，或把仅原点可行等同全路径通过。当前模型的整段来源证书是相对于输入折线的证书，不是实际未采样道路的测绘证明。

下一步顺序：

1. 建立原点观测与点间推断的分别记账，明确原采样误差/弦距依据，以及原标量宽度、实际车道法向宽度与参考轴t向width的关系；在保持同身份全路径报告的前提下评估共享道路模型，不能简单取消整段门禁。
2. 把普通路初始化从“固定轴先通过”改为同一联合可行性问题，评估合法事件站位和少量参考轴模型；沿用三回旋线连接/长边界基底，不以小段增自由度。
3. 对node13 road12保留精确冲突点、宽度及身份，检查结构分组/常宽模型；尚无依据修改原件或扩大容差。
4. 可行之后再做写出读回、宽度/中心/边缘/动态/孔洞/esmini全接口与完整视角截图。SHP使用其真实边界合同，不照搬MAP标量宽度假设。Web仍待同一内核可用纵切，未开发完成。

## 5. 文献核查如何影响实现

- Gould、Toint，*SQP methods for large-scale nonlinear programming*，第2.1节解释非线性约束线性化和二阶校正相关问题。[作者全文](https://www.numerical.rl.ac.uk/media/people/nick-gould/GoulToin00_tc7.pdf)。本轮参考其对真实约束回算的要求；只实现最小改动法向步骤/回溯，未实现论文二阶校正。实测导数错误另有明确反例，不能用文献概念掩盖。
- T/CMAX 24001—2022的DF_Lane字段表区分laneWidth车道宽度与Points车道中心位置点。[全国团体标准信息平台原文](https://www.ttbz.org.cn/Home/PdfFileStreamGet/c3QsNjU0NzM%28eq%29)。这是相邻标准的语义核查，不替代本项目T/CSAE版本及本地资料；没有从此推出“所有站位必须等宽”的标准条款。没有复用外部项目代码或新增第三方依赖。
- ASAM OpenDRIVE 1.8.1 §11.6.1明确width沿参考坐标t方向变化。[官方规范](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/11_lanes/11_06_lane_geometry.html)。这促使本轮明确上述度量限制；不能把倾斜坐标图中的常量width合同当作坐标不变的物理宽度认证。目标写出版本仍为本地1.5M，不引入1.8新元素。
