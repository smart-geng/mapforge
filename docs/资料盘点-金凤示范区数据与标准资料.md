## 二、SHP 交付：IBD 规格解剖

### 2.1 版本与坐标

- `IBD_VERSION`：EDIT_VER=**IBD_V1.0.0**，APP_VER=**smarteditor**（编辑工具），COORD_SYS=**84**（声称 WGS84），COORD_UNIT=2（度），CREATETIME=2023-11-15。
- `.prj` 全部为**自定义 WKT**：`GEOGCS["My geographic coordinate system", DATUM["D_WGS_1984", SPHEROID["My_WGS84_Spheroid",...]]]`——无 EPSG 码，工具随手生成的痕迹。**声称 WGS84 但未证实**（结合 xml2xodr 存在 GCJ02 纠偏开关，坐标真伪必须实测核验后才能进生产，见方案 4.3 CRS 硬约束）。
- 几何全部带 Z（PolyLineZ/PointZ），高程 242–320 m（重庆合理范围，疑似正常高，垂直基准未声明）。
- DBF LDID=0x57（ANSI），实际中文内容按 GBK 解码正常（ROADNAME="高新大道辅路"、NAME="高新大道-白鹭大道"）。

### 2.2 单位与 ID 约定

- 长度/宽度单位**毫米**（WIDTH=3500 → 3.5 m；LENGTH=155071 → 155 m；MARK_WIDTH=200 → 0.2 m）；速度 **km/h**（MAX_SPEED=40/60）；角度**度**（HEADING 0–360）；曲率 1/m、坡度/超高带 4–6 位小数。
- 主键 `*_PID`：19 位数字串，前 8 位是编辑日期（如 2023041211102754016）；另带 GUID 列；MESH 为图幅号。
- 关系表借壳空几何 PolyLineZ 存纯属性（bbox 全 0），是"用 shp 装关系表"的惯用做法。

### 2.4 对转换流水线的直接影响

1. **SHP→MAP 的 connectsTo 不再依赖几何推断**：LANE_TOPO_DETAIL（IN→OUT）+ LANE_LINK_MERGE（S_JUN/E_JUN）给出显式车道级拓扑 → 转换状态从 INFERRED 升级为 EXACT/TRANSFORMED，人工复核压力大幅下降（几何推断降级为缺失兜底）。
2. **交叉口发现免推断**：INTERSECTION_SURFACE 的 ENTER_ROAD/LEAVE_ROAD 直接给出进出 Link 集合。
3. **maneuvers 数据源**：ARROW.DIRECTION（车道级地面箭头）为主，路口内虚拟车道几何方位角为辅。
4. **SHP→OpenDRIVE 拟合数据源**：LANE_POSITION/POSITION 是独立密集采样点层（~1 m 间距，PointZ 自带几何，非 LANE_LINK 形点属性），点密度优秀。**（2026-08-13 Spike-C 核验）逐点姿态字段可信度分化：HEADING 与几何航向吻合（北向、度）可用；CURVATURE 与几何曲率整体不相关（150 条车道批量核验，相关系数中位 -0.005，仅 2/150 条 |corr|>0.5；典型矛盾：字段记 R≈60–128 m 弯而几何为直线）不可作先验，语义待向交付方确认；SLOPE/BANKING 未核验、按同等怀疑对待。**
5. **真实脏数据清单（Profile 引擎必须容忍）**：
   - UPDOWN_DIR 字段数值溢出成 `****`（DBF N 字段写坏）；
   - 同名字段单位不一致：CENTRE_X/Y 在 ARROW/SYMBOL/TEXT 是投影米（如 629033, 3267021），在 TRAFFIC_LIGHTS 是经纬度（106.33, 29.51）——**字段语义必须按图层配置，值域探测不可省**；
   - 字段名 10 字符截断（STOPLINE_R、PROVINCE_L/R）；
   - 字段宽度全部虚标（C,100/150/254），DBF 以空格填充，文件因此虚胖（IBD_POSITION.dbf 470MB）；
   - 关系表借壳空几何；.prj 自定义 WKT 无 EPSG；
   - **字段内容与字段名不符的整层案例**：LANE_POSITION.CURVATURE 与实际几何曲率不相关（见上第 4 条）——字段级核验（值域探测 + 与几何交叉验证）必须是 Profile 引擎的强制步骤，不能信任字段名。

## 三、V2X MAP 标准资料

### 3.1 消息层技术要求 docx（标准正文）

- 封面标准号为 **YD/T XXXX—XXXX 占位**（送审/报批稿），前言引用 YD/T 3400-2018、YD/T 3340-2018——即后来发布的 YD/T 3709《基于LTE的车联网无线通信技术 消息层技术要求》的定稿前文本。
- 内容：消息帧-消息体-数据帧-数据元素四层定义，UPER 编码；**MessageFrame ::= CHOICE {bsmFrame, mapFrame, rsmFrame, spatFrame, rsiFrame, ...}** 五消息齐全；每个数据帧/数据元素带【定义】释义与【ASN.1代码】。
- MAP 关键定义与方案 2.3 节假设一致：MapData{msgCnt, timeStamp OPTIONAL, nodes NodeList}；DF_Movement 明文："相位ID事实上也是MAP消息与SPAT消息的唯一关联"（Movement{remoteIntersection NodeReferenceID, phaseId PhaseID OPTIONAL}）。
- **对 M0 的影响：方案 v1.0 唯一前置依赖"购买标准正文提取 ASN.1"已被此资料解除**（正式发布前仍建议购正式版 YD/T 3709-2020 做差异核对，送审稿与发布稿可能有细节出入）。

### 3.2 ASN.1 源码文件（v1.0.1）——是 TCI 控制协议，不是消息层本体

- 模块名 `TciMsgLayerFrame`（AUTOMATIC TAGS，无 OID/版权声明，1008 行）。顶层 `TciMsgLayer{version(=2), msgNo, msgFrame TciMsgFrame}`，`TciMsgFrame ::= CHOICE {request, response, indication, exceptionInfo, ...}`——**测试系统(TS)↔被测设备(DUT)的一致性测试控制协议**：7 种控制消息（SetInitialState / Start·StopMsgLayerTx / Start·StopMsgLayerRx / SetBsmInfo / SetRsmInfo）+ 收包上报（eBsmRx/eMapRx/eRsmRx/eSpatRx/eRsiRx）。
- **文件中不存在 MessageFrame/MapData/NodeList/Link/Lane/Movement 的完整定义**——MAP 只有概要上报类型（BasicMapNodesInfo/BasicMapLinkInfo/BasicMapLaneInfo/RxMapInfo）。→ **不能直接用它编译出 MAP 编解码器**。
- 但它完整定义了一批与消息层同名同构的子类型，与 7 个 XML 逐字段吻合，可作核对参照：`NodeReferenceID{region OPTIONAL, id}`、`Connection{remoteIntersection, connectingLane OPTIONAL, phaseId OPTIONAL}`、`ConnectingLane{lane, maneuver OPTIONAL}`、`AllowedManeuvers BIT STRING(SIZE(12))`（位 0-11：straight/left/right/uTurn/leftTurnOnRed/rightTurnOnRed/laneChange/noStopping/yieldAllwaysRequired/goWithHalt/caution/reserved，**无扩展标记**）、`SpeedLimitList(1..9) OF RegulatorySpeedLimit{type, speed}`（13 种限速类型带 `...`）、`PositionOffsetLL ::= CHOICE` 7 分支（position-LL1..LL6 偏移档位，注释 LSB=0.1 微度，±22.6m 至 ±92.8km + position-LatLon 绝对分支）、`VerticalOffset` 7 分支。
- 关键取值约束（可直接进 MapIR 校验规则）：Latitude -9e8..9e8+1（1e-7°）、Longitude -1799999999..1800000001、Elevation -4096..61439（0.1 m）、NodeID/RoadRegulatorID 0..65535、LaneID 0..255、PhaseID 0..255、LaneWidth 0..32767（1 cm）、TimeMark 0..36001（0.1 s）。
- 注释大量出现"参考《基于LTE的车联网无线通信技术 消息层技术要求》中 DF_xxx/DE_xxx"——**字段语义外包给同目录 docx**，两份资料是配套关系。
- 对项目的定位：① 消息层子类型核对参照与约束表来源；② **FusionTest 侧资产**（设备消息层一致性测试的控制协议，正是测试框架可消费的东西）；③ 不承担 MAP codec 编译职责。
- **结论：消息层本体 ASN.1 的获取路径 = 从 docx 的【ASN.1代码】块逐段提取拼装 + 用 TCI 子类型与 7 个 XML 实例双向核对**——这成为 M0 的第一个工程作业（替代原"购买标准正文"前置依赖）。

### 3.3 7 个路口 MAP XML

- **标准 MessageFrame 的 XER 风格实例**（逐字段元素化，枚举=空元素、BIT STRING=01 串、CHOICE=分支名元素；无属性、无命名空间）。结构：MessageFrame > mapFrame > {msgCnt, timeStamp, nodes > Node ×1}；Node > {name, id{region,id}, refPos, inLinks > Link ×4（name 固定 west/north/east/south）}；Link > {upstreamNodeId, linkWidth, points, movements > Movement{remoteIntersection, phaseId} ×3, lanes > Lane ×2-4}；Lane > {laneID, laneWidth, maneuvers, connectsTo > Connection{remoteIntersection, connectingLane{lane,maneuver}, phaseId}, [speedLimits], points}。量级：每文件 1 Node / 4 Link / 8-16 Lane / 44-113 RoadPoint。
- msgCnt/timeStamp 各文件不同（18-120 / 203493-203588，后者是 MinuteOfTheYear 量级）→ **更像从实际播发流导出的单帧快照**，而非手写模板。
- **坐标：全部走 position-LatLon 绝对经纬度分支（1e-7° 整数），7 个文件无一使用偏移编码分支**——现网实践未用 offset 压缩（消息偏大），mapforge 的偏移编码输出反而是增量价值；同时 v2xmap reader 必须兼容"绝对坐标点列"方言。
- **高程：仅 node13 有，且恒为 500（=50 m，与当地实际海拔 242-320 m 不符，显然是占位值）**——现网 MAP 基本无真实高程。
- **ID 体系混乱（实锤，直接决定台账清洗优先级）**：

| 文件 | region | Node id | 文件名一致? | 邻居 id |
|---|---|---|---|---|
| 含金路-金玥路node3 | **3** | 3（name=node_c） | id 一致 | 1, 2, 4 |
| 凤苑路-金玥路node4 | 500 | 4 | 一致 | 3, 9, 18, 401 |
| 凤苑路-金坪路NODE5 | 500 | 5 | 一致 | 21501, 20603, 20702, 20703 |
| 凤阁路-金玥路node13 | **21901** | 21901 | **不一致** | 3, 21803, 21903, 22003 |
| 凤阁路-金剑路node16 | 500 | **21801** | **不一致** | 21204, 21301, 21803, 22001 |
| 含金路-金剑路node17 | 500 | 17 | 一致 | 15, 16, 18, 22 |

  region 三种取值混用（500=重庆区划前缀 / 21901 / 3）；小场地号（1-23）与 5 位码（2xxxx）两套编号并存甚至同文件混用；**交叉引用失配**：node17 引用邻居 (500,16)，node16 文件自称 (500,21801)；node13 引用 (21901,3)，node3 自称 (3,3)。→ 这批数据进黄金测试集前必须先做 **ID 台账清洗**（唯一化 + 引用修复 + 登记为 `ledger/` 初始台账）。
- **phaseId 现网样例**（7 文件取值集合完全相同 {0,1,2,9,10,17,18,25,26}）：每进口两个相位、编号间隔 8（north 1/2、east 9/10、south 17/18、west 25/26）；**右转一律 phaseId=0**（"不受灯控"的现网表达习惯）；左转用每对第一个、直行用第二个。node3 整个缺 movements 层但 Connection 仍带 phaseId。→ 黄金测试集自带真实 phase 绑定样例；"phaseId=0 表示无灯控"应写入 v2xmap Profile 的方言语义。
- speedLimits 仅 node3/4/18 三个文件有（Lane 级，vehicleMaxSpeed，speed=833 按 0.02 m/s 即 60 km/h）。
- 方言容错点：maneuvers 的 01 串值两侧带换行缩进空白（解析需 strip）；movements 层可整体缺失；refPos 字段名 lat/long（XER 下的标准命名）。

## 四、xml2xodr 参考代码评估

既有内部代码（2023，无版本管理/测试/README，按文件名日期迭代），实现 MAP XML→OpenDRIVE 1.5。

### 4.1 值得吸收

1. **MAP XML 字段与单位换算表**（v2xmap adapter 对照物）：坐标 1e-7 度、laneWidth/linkWidth **厘米**、速度 **0.02 m/s**、高程**分米**；Node→Link(upstreamNodeId)→Lane(connectsTo/maneuvers 12 位位串/phaseId)→RoadPoint 解析层级完整。
2. **局部切面投影选型**：以路口 refPos 为原点 `+proj=sterea +ellps=GRS80` 平面投影 + geoReference 写 PROJ 串（方向正确；mapforge 应改为规范 CRS 管线记录而非 lxml 后处理注入——其 modify_header 会追加出重复 geoReference，已有脏输出实例）。
3. **GCJ02/BD09 纠偏开关（location_type）的存在本身**：证明现场 MAP 数据确实可能是火星坐标——"CRS 可疑即停"硬约束的实证依据。
4. **车道对齐重建思路**：以最长车道为虚拟参考线投影重采样对齐各车道点列，逐段实测相邻车道间距得到起止变宽（road_info.py 的 align_lanes + reference_line_tuple_with_width）——车道级宽度重建的可用雏形。
5. **反面教训**："每两点一条 road"方案导致接缝补丁链（缩段 20–30% + AdjustablePlanview 过渡 + 手工 pred/succ 串联）——反向论证必须做整条参考线连续拟合。

### 4.2 必须抛弃/重写

- 逐段 Line 几何（无曲率连续性）；高程解析后丢弃（xodr elevationProfile 恒空）；
- **connectsTo/movement/phaseId 解析了但从未消费——没有任何脚本生成 junction/laneLink**（所有输出 road 均 junction="-1"）；xodr 目录里带 junction 的 a_intersection*.xodr 是 scenariogeneration 官方示例的手工试验残留，无对应脚本；
- maps-0605.py（最新版）依赖本地魔改库私有函数 `create_road_geng`，仓库不自包含、不可复现；
- 手写 GCJ02 近似互转脚本（网络流传版）；字符串拼接式 XML 序列化；入口路径/魔数硬编码（+0.4 m 车道加宽、road_id 拼号会撞号）；裸 except 吞错；限速解析后未消费。

### 4.3 结论

**这条内部链路证明"MAP→OpenDRIVE"有真实业务需求**（把现网 MAP 变成仿真可用地图），但现状产物是"无路口、无高程、不可复现"的骨架——mapforge 的 MAP→xodr 方向（方案原 P2）应上调优先级，并以"junction 完整生成 + 高程保留 + 连续参考线"为对既有链路的替代价值。

## 五、OpenDRIVE XSD

- `OpenDRIVE_1.4H.xsd`：VIRES 官方 Rev. 1.4H（©2015），`OpenDRIVE_1.5M.xsd`：Rev. 1.5M（©2019），均注明 excluding SET records。
- 与 xml2xodr 输出 revMinor=5 相互印证：**本地既有工具链的 OpenDRIVE 基线是 1.4/1.5**。
- 影响：方案写出版本策略需覆盖 1.5（见方案 v1.1 第 1.1 节修订）；两份 XSD 直接纳入 `validate/` 的 XSD 门禁资产。
